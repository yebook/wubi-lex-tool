# S0-06 短语与辅助文本编解码

## Goal

完成 `wubilex-codec` 在 S0 剩余的文本格式边界：把社区短语文本、词频文件和拆字数据表严格转换为保序强类型文档，并从码表内容确定性探测八种方案，为后续 EUDP 往返、词频处理、反查资源和真实 fixture 回归提供可测试合同。

## Background

- 权威行为来自 `docs/01-data-formats.md` 第 4 至 8 节，以及 M1/M2/M3 模块需求；旧 aardio 代码只用于核对兼容控制流。
- `PhraseDocument` 已固定为保序、保留重复项的 entry stream，候选位序为 `1..=255`；EUDP 原始字节编解码已经完成。
- 码表文本任务已经实现严格 UTF-8、UTF-16LE/BE、GBK 探测和六种 ASCII 空白转义，本任务复用该合同，不复制或放宽解码逻辑。
- `LexScheme` 已覆盖 86、98、06、091、092、郑码及其构词表变体、小鹤音形和表形码，本任务实现内容探测。
- 旧短语解析器会静默忽略未识别行；沿用已批准的兼容策略：保留可导入行为，但将未知非空行作为有界可见警告返回。
- 根目录 `resource/` 是用户所有的本机样本目录，本任务不读取、不修改、不暂存、不提交，也不让自动化测试依赖它。

## In Scope

1. 从原始字节严格解码短语文本，复用 BOM 优先的 UTF-8、UTF-16LE/BE、GBK 探测并返回编码元数据。
2. 剥离跨行 `/* ... */` 注释，按固定优先级解析 P1 至 P6，保留原始行列位置。
3. 实现多行短语、`$[...]` 展开、显式与自动候选位序、P2 时间变量别名及共享空白反转义。
4. 把 `PhraseDocument` 规范输出为候选明细或可压缩的 `$[...]` 文本，固定排序、转义和 CRLF。
5. 严格解析并规范写出无 BOM UTF-8 词频文件，覆盖非空无空白词条和 `1..=65535` 权重。
6. 严格解析并规范写出无 BOM UTF-8 拆字数据表，原样保留 Unicode 私用区字根。
7. 按文档顺序执行五组直接判定和 86/98/06/091 打分判定，覆盖八种方案及郑码构词表变体。
8. 对所有文本解析执行输入字节、展开条目、checked arithmetic 和结构化位置检查，并以合成测试固定兼容行为。

## Out Of Scope

- EUDP 二进制布局、时间戳和 tombstone 处理；已由 `s0-eudp` 完成。
- 文件路径、系统短语 v1/v2 择新、双写、备份、Windows 版本判断、注册表、TSF 和 Tauri command。
- 词频重排、保持首单字、权重重算、短语分离、拆字词组组合与倒排索引；这些属于 `wubilex-core`。
- 词频或拆字资源的下载、LZMA 解压、缓存、字体和镜像；这些属于 `wubilex-resource`。
- CSV/JSON 码表容器、默认 36 条短语库、编辑器或 UI 中的时间变量警告。
- 真实 fixture 获取、八方案真实样本回归和 codec 全局 90% 覆盖率出口；集中到 `s0-fixtures-regressions`。

## Requirements

| ID | Requirement |
|---|---|
| PA-R01 | 新能力保持纯同步、内存到内存并位于 `wubilex-codec`；不得引入文件系统、平台、网络、Tauri、Tokio 或新的第三方依赖。 |
| PA-R02 | 短语 decode 复用现有严格编码选择：完整输入上限先于解码，BOM 优先；成功结果返回探测元数据，非法 UTF-8/UTF-16/GBK 返回原始零起字节偏移。 |
| PA-R03 | `/* ... */` 注释按非贪婪跨行规则移除且保留后续原始行列；未闭合注释是带起始位置的错误，空白或仅注释文档可得到空文档。 |
| PA-R04 | P1..P6 按文档顺序尝试；已识别语法中的非法 code、空文本或候选位序必须在所属字段失败，不得降级为 warning 或另一方言。 |
| PA-R05 | P2/P3 的空文本进入 multiline；后续非空未识别行以 `\n` 追加，遇到下一条可识别记录结束；输入结束时累计文本不得为空。 |
| PA-R06 | 普通无显式候选记录按同 code 已用最大候选 +1；`$[...]` 仅在无显式候选时展开，含 ASCII 空格则归一化后分词，否则按 Unicode scalar 分割，数组候选固定为 `1..=N` 并把该 code 最大值更新为 `max(old, N)`；任何结果必须适配 `1..=255`。 |
| PA-R07 | P2 中九个 `$` 别名转换为微软 `%...%` 变量，未知别名保持字面值；短语字段复用 `%20/%09/%0A/%0D/%0B/%0C` 对称反转义。 |
| PA-R08 | 短语未知非空行产生有序 `UnrecognizedLine` warning，含原始行号、最多 160 个 Unicode scalar 的预览和截断标志；entry 与 warning 共用展开预算，非空正文零 entry 仍返回错误。 |
| PA-R09 | 短语格式化按 code 字典序、同 code candidate 升序稳定排列；只有多条、候选连续从 1 开始且每条不超过 2 个 UTF-16 单元时压缩为 `$[...]`，否则输出明细；全部文本转义并用 CRLF。 |
| PA-R10 | 词频格式只接受无 BOM UTF-8 的 `<word><whitespace><weight>` 非空行，word 不含 Unicode 空白，weight 为 `1..=65535`；规范输出为 `word<TAB>weight<LF>`。 |
| PA-R11 | 拆字表只接受无 BOM UTF-8 的 `<term><whitespace><roots>` 非空行，两字段均非空且不含 Unicode 空白；规范输出为 `term<TAB>roots<LF>`，PUA 和非 BMP scalar 原样保留。 |
| PA-R12 | 词频与拆字文档保持输入顺序和重复项，空文件合法；任何非空损坏行严格失败并给出 1 起 line/column，重复项的 map 覆盖策略留给 core。 |
| PA-R13 | 方案探测先按郑码、小鹤、郑码构词表、092、表形码顺序直接判定；命中某组全部特征立即返回，权重和重复项不影响命中。 |
| PA-R14 | 未直接命中时逐项执行 86/98/06/091 评分，使用小写 `xfxy` 修复旧缺陷；98、06、091 仅在严格高于其余三者时胜出，其余平局和不确定输入兜底 86。 |
| PA-R15 | 每次追加 phrase/word/spelling entry 或 warning 前检查 `max_expanded_entries`，算术和容量使用 checked 路径；错误不返回部分文档，生产代码不得 panic、lossy decode 或使用 `unwrap`/`expect`。 |
| PA-R16 | 合成测试覆盖六方言、注释、多行、数组、时间变量、转义、短语规范输出、两个辅助表、八方案、`xfxy` 回归、损坏输入和资源边界；不得访问 `resource/`。 |

## Acceptance Criteria

- [ ] 同一短语文本的 UTF-8（有/无 BOM）、UTF-16LE/BE BOM 和 GBK 字节均产生相同 `PhraseDocument`，编码元数据和非法字节偏移准确。
- [ ] P1..P6 各有独立测试；混合输入按固定优先级产生正确 code/text/candidate，已识别损坏字段不会落入 warning。
- [ ] 跨行注释、多行短语、九个时间别名、未知别名和空白转义均有完整行列及往返断言。
- [ ] `$[...]` 的逐字符/空格分词、候选最大值、显式位序、自动最大值 +1 和溢出路径全部可观测且不产生部分文档。
- [ ] 未识别行按源顺序返回有界可见 warning；未知行后续合法记录仍导入，未知-only 非空输入返回错误。
- [ ] PhraseDocument 的规范文本完整字符串与手写期望一致，覆盖 CRLF、稳定排序、重复候选、候选缺口、emoji 和 `$[...]` 压缩边界。
- [ ] 词频文件严格解析/写出覆盖空文档、重复词条、最小/最大权重、BOM、非法 UTF-8、额外字段和精确位置。
- [ ] 拆字表严格解析/写出覆盖空文档、重复词条、PUA、emoji、空字段、额外字段和精确位置。
- [ ] 直接判定覆盖郑码、郑码构词表、小鹤、092、表形码；打分覆盖 86/98/06/091、严格胜出、平局兜底和小写 `xfxy` 失败到通过回归。
- [ ] 所有解析器在输入与展开条目上限边界通过，超一即返回准确 `ResourceLimitExceeded`；代表性截断/损坏输入不 panic。
- [ ] 自动化测试和实现不读取、修改或提交 `resource/`，也不新增平台、异步、网络或文件系统依赖。
- [ ] `cargo fmt`、严格 Clippy、codec/workspace 测试、Rustdoc、全局 pnpm 静态门禁、文档锚点和 Trellis 检查通过。

## Risks And Deferred Items

- P2/P3 multiline 会把原本未知的非空行解释为正文；这是文档指定的状态语义，测试必须固定其终止条件，避免 warning 策略误吞或误报正文。
- 字面 `%20` 与真正空格仍无法区分；沿用现有共享转义合同，不引入不兼容的 `%25`。
- 词频与拆字旧实现把重复 key 覆盖为最后一条；codec 保序保重复以支持审计和往返，core 后续建立查询 map 时再显式固定 last-wins 或拒绝策略。
- 方案打分是兼容启发式，不保证任意裁剪码表都能识别；无严格赢家时固定返回 86，不把低置信度推断包装成错误。
