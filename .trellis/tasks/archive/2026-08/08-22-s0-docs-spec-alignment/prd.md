# S0-00 文档与规范校正

## Goal

在写入任何 S0 产品代码前，修复路线图中会导致错误验收或错误排期的现有口径冲突，并把已经定案、且适用于 S0 的项目合同写入首批 Trellis 开发规范。

## Background

- `docs/22-roadmap.md:119` 写 P0 共 200 条，但同文档汇总与 S7 出口均为 208 条。
- `docs/22-roadmap.md:244,254` 写 8 个缺陷，而 `docs/02-architecture.md:776-785` 与 `NFR-MAINT-004` 明确只有 6 个。
- 6 个缺陷中，`XFXY`、空白转义、`codeWeight[0]` 属 S0 codec；短语拖放、郑码造词、`unique()` 属编辑/变换阶段，不应迫使 S0 提前实现 S4。
- `docs/22-roadmap.md:246` 说预研不阻塞 S1，但 `:556,565` 两次要求在 S1 前完成或复评。
- backend/frontend Trellis 规范大多仍为模板；目录、错误、类型和质量合同已经在架构与需求文档中定案，但尚无真实源代码示例。

## Acceptance Criteria

- [ ] `docs/22-roadmap.md` 对 P0 总数只使用 208。
- [ ] 路线图、架构和 `NFR-MAINT-004` 对已知缺陷总数只使用 6。
- [ ] S0 只要求 `XFXY`、空白转义、`codeWeight[0]` 三项 codec 回归通过。
- [ ] S4 覆盖 `M2-IO-005..007`、`M2-COIN-001` 和 `M1-SLIM-007` 对应回归。
- [ ] 技术预研的所有说明均与“S1 前通过或复评”的门槛一致。
- [ ] 六份首批 spec 使用英文、不含 `To be filled`，且每条规则有现有文档或目录依据。
- [ ] 未覆盖规范在 index 中明确标记为待实际实现补充，不伪装完成。
- [ ] crate README 不再声称 S0 关闭 8 个缺陷，也不再把技术预研推迟到 S3 前。
- [ ] 模块/NFR/UX 需求计数保持 414/101/115，总计 630。
- [ ] 需求定义行无重复，引用无悬空，`docs/` 无占位符，内部锚点 0 失效。
- [ ] 没有新增 Cargo、pnpm、Tauri 配置或任何产品源码。

## Out Of Scope

- 创建或修改可编译工程配置和产品源码。
- 实现任何 codec、UI、系统集成或技术预研原型。
- 在没有真实代码证据时完成并归档 `00-bootstrap-guidelines`。
- 改动 `wubi-lex/` 历史快照。
