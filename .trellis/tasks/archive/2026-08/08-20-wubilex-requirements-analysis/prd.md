# WubiLex 原项目需求分析与 Rust+Tauri 新项目需求文档

## Goal

对 `wubi-lex/` 目录下的 aardio 开源项目 WubiLex（五笔助手 v12.1）做**全量**功能与技术分析，产出一套可直接驱动新项目（Rust + Tauri，全新现代化 UI）开发的需求文档集。文档按功能模块拆分为多个文件，每个模块逐条列出功能需求，并标注 P0/P1/P2 优先级与实现风险。

## Scope

### In scope

- 原项目 32 个 `.aardio` 源文件（7,574 行）的全量功能梳理
- 逆向并成文的二进制/文本数据格式规格（`.lex` 码表、EUDP 短语、文本码表方言、词频文件、拆字数据表）
- 7 个功能模块的需求清单，每条需求带唯一 ID、描述、优先级、来源文件、实现风险
- 非功能需求（性能、权限、兼容性、可靠性、安全）
- 现代化 UI/UX 需求
- Rust + Tauri 架构映射（aardio 能力 → Rust crate / Tauri command）与风险登记
- 优先级汇总与里程碑路线图

### Out of scope

- 实际编写 Rust / Tauri 代码
- 新项目脚手架搭建
- UI 视觉稿 / 高保真设计
- 跨平台（本任务按用户决策限定 **Windows 独占**）

## Constraints

- **目标平台**：仅 Windows（Win10 1703+ / Win11）。原项目深度依赖 TSF、注册表、微软五笔 IME、TrustedInstaller ACL，不做跨平台抽象。
- **范围界定**：全量分析，不裁剪功能；通过 P0/P1/P2 分级 + 风险标注让后续决策者自行取舍。
- **文档语言**：简体中文。
- **文档位置**：仓库根目录 `docs/`，与 Trellis 任务产物分离，便于新项目直接引用。
- 需求必须**可追溯**：每条需求标注原项目来源文件与行为依据，禁止臆造功能。

## Requirements

- R1 产出文档索引 `docs/README.md`，说明文档集结构与阅读顺序。
- R2 产出 `docs/00-overview.md`：项目背景、目标、原项目现状分析、模块地图、术语表、优先级定义。
- R3 产出 `docs/01-data-formats.md`：逐字段规格化描述 5 类数据格式，含偏移表、字段语义、解析算法、边界条件。
- R4 产出 `docs/02-architecture.md`：Rust + Tauri 分层架构、crate 划分、Tauri command/event 契约、依赖选型、aardio→Rust 能力映射表、风险登记册。
- R5 产出 7 份模块需求文档 `docs/modules/M1..M7-*.md`，每份包含：模块职责、功能需求逐条清单（带 ID/优先级/来源/验收要点）、数据依赖、对外接口、风险。
  - M1 码表管理
  - M2 短语词库
  - M3 反查拆字
  - M4 输入法控制与系统设置
  - M5 字根图与帮助资料
  - M6 资源分发与网络同步
  - M7 应用外壳（窗口/托盘/热键/配置/更新）
- R6 产出 `docs/20-nonfunctional.md`：性能、权限、兼容性、可靠性、安全、可观测性、i18n、可访问性需求。
- R7 产出 `docs/21-ui-ux.md`：现代化 UI 的信息架构、导航模型、关键界面需求、交互规范、主题与设计令牌、大数据量列表/编辑器策略。
- R8 产出 `docs/22-roadmap.md`：全量需求优先级汇总表 + 里程碑拆分。
