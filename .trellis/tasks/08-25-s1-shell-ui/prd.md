# S1 外壳与 UI 骨架

## Goal

交付第一个可运行、可点击、可对外演示的 WubiLex Windows 应用。S1 一次建立后续领域功能共同依赖的进程生命周期、配置、窗口与托盘、事件与任务、动作与快捷键、主题、导航和反馈骨架；S2 及以后只需把规范占位替换为真实领域能力。

## User Value

- 用户能立即看见产品的完整形状，并通过鼠标或键盘访问全部七个领域。
- 主题、窗口、托盘、快捷键和配置在重启后行为稳定，不需要每个领域重复建设。
- 尚未实现的能力保持可发现，但明确说明交付阶段，不产生“按钮坏了”或误操作系统的错觉。
- 长任务、失败和空数据都有一致、可恢复、不中断浏览的反馈入口。

## Background And Confirmed Facts

- S0、四项风险预研和 S0 集成已完成；S1 入口门槛满足。
- 当前 `src/` 只有生成的 IPC 类型，尚无 React 入口、路由、产品组件或状态存储；`src-tauri` 只有绑定注册基线，尚不可启动产品窗口。
- 技术栈已定案为 Tauri 2、React 19、TypeScript、Tailwind CSS v4、shadcn/ui、Lucide、Zustand、React Router 和 i18next。
- Rust 是 IPC command、event 和共享类型的唯一事实来源；生成文件由 `cargo xtask bindings` 管理。
- 配置采用自建 `serde` + TOML，不使用 `tauri-plugin-store`；功能可用性采用 Cargo feature + `app_features` command 双端驱动，不使用 Vite 常量。
- 一期接受整进程管理员权限，并必须向用户说明原因；提权辅助进程是后续演进方向。
- Node/pnpm 只由 `package.json.volta.node` 和 `package.json.volta.pnpm` 固定；禁止 `packageManager`、`engines.pnpm`、Corepack、npm、yarn 和 npx。
- 根目录 `resource/` 不属于 S1 规划或实现输入，不得读取、修改或纳入自动化测试。

## In Scope

### 1. 可运行应用与生命周期

- 建立真实的 Vite/React 入口、Tauri desktop entry、开发与构建配置，使应用可以本地启动和构建。
- 实现单实例：重复启动时把已有窗口置前，并把合法启动参数转交给主实例。
- 实现一期管理员权限声明、运行时权限检测和首次运行知情说明；权限不足时给出可执行的中文提示。
- 支持普通启动、`/tray` 静默启动和内部深链接参数；未知参数可见报错但不导致崩溃。
- 建立运行会话标记，区分正常退出与异常退出。S1 提供恢复检查入口和可见警告；真正的 TSF/服务/ACL 恢复动作仍由 S3 实现。
- 补齐产品名称、版本、图标、公司和版权等应用元数据。

### 2. 窗口与托盘

- 提供无边框主窗口、自定义标题栏、最小化/最大化/还原/关闭控制和高 DPI、多显示器下的自适应行为。
- 支持“最小化到托盘”与“直接退出”两种关闭行为，默认最小化到托盘。
- 持久化窗口尺寸、位置和最大化状态；恢复时校正到当前显示器可见工作区，不能把窗口恢复到屏幕外。
- 窗口子任务只实现托盘图标的还原、置前、退出，以及“显示 WubiLex / 退出”两项必要菜单；统一动作目录与路由存在后再扩展完整菜单，不提前加入领域占位或 S3 系统写入入口。
- `/tray` 启动不闪现主窗口，并按需求延迟创建托盘图标。

### 3. 配置、功能开关与持久状态

- 定义带 `schemaVersion` 的强类型配置，覆盖主题、密度、语言、窗口、关闭行为、首次引导和快捷键绑定。
- 配置首次运行补默认值、分组即时保存、进程退出保存、原子替换和写前备份。
- TOML 损坏或迁移失败时保留损坏副本、回退默认值并向用户显示可恢复警告，不能阻止应用启动。
- 支持配置导出/导入；导入先解析和校验，失败不得覆盖当前有效配置。
- Cargo features 是功能可用性的唯一来源；`app_features` 通过生成的 IPC 类型填充 Zustand feature store。

### 4. 事件、任务与错误

- 建立强类型事件目录和 Tauri emit/listen 桥接；S1 注册 M7 事件契约，后续模块在各自阶段接入真实生产者。
- 建立统一后台任务注册表：任务 ID、阶段、百分比、可取消性、状态查询、互斥组和协作式取消。
- 任何可能超过 100 ms 的工作不得阻塞 UI 线程；任务反馈按时长分级，长任务在常驻状态栏非模态呈现。
- 任务进度组件同时提供状态栏和不可中断阶段遮罩两种形态；S1 用合成状态验收 12 阶段展示，S3 才接入真实 TSF 停机流程。
- 提供统一中文错误模型和错误详情面板，覆盖“发生了什么 / 为什么 / 怎么办”、技术详情和一键复制。
- 建立成功 toast、持久失败提示、空状态、后果明确的确认框、未保存拦截和文件拖放反馈。

### 5. 动作、命令面板与快捷键

- Rust 侧动作注册表是动作 ID、名称键、分组、作用域、默认绑定和可用阶段的唯一事实来源；UI、命令面板和快捷键设置共用它，后续扩展的领域托盘菜单也必须从该目录投影。
- 命令面板可搜索全部动作并执行当前可用动作，至少覆盖七个页面跳转、主题、窗口和设置入口；不可用动作显示阶段说明。
- 应用内快捷键与系统全局热键使用不同作用域和冲突域；默认绑定采用 M7 的新版动作表，其中最小化为 `Ctrl+Shift+H`，不沿袭旧版 `Ctrl+W`。
- 快捷键设置支持搜索、录制、`Esc` 取消、`Del` 清除、应用内冲突提示、系统占用提示、保留旧绑定、单项/全部恢复默认和导入/导出。
- 全局热键变更即时生效；注册失败时当前有效绑定和持久化配置均保持不变。
- 拒绝系统保留组合，并给出明确原因。

### 6. 视觉系统与应用骨架

- `src/styles/theme.css` 是颜色、间距、圆角、字号、阴影和动效令牌的唯一来源；主题相关令牌使用 Tailwind v4 `@theme inline`。
- 实现墨蓝主色、朱砂危险色、冷灰中性色、三层表面和五区具名颜色；深浅主题分别满足对比度。
- 支持浅色、深色、跟随系统三种主题，以及标准/紧凑两档密度；主题在首帧前确定，不闪白。
- 统一使用 Lucide 图标并提供可访问名称；不使用 emoji、图标字体或硬编码 SVG 作为结构图标。
- 应用布局由固定可折叠侧栏、轻量应用栏、内容区和常驻状态栏组成，最小可用窗口为 `1024x640`。
- 一级导航为概览、码表、短语、反查、字根、学习、设置。旧版“帮助”内容按新版 IA 归入字根和设置，不恢复旧的四项顶栏结构。
- 所有页面和主要状态有稳定内部路由，支持命令面板、托盘和启动参数深链接，并提供 `Esc` / `Alt+Left` 返回语义。

### 7. 页面与占位

- 概览页提供健康告警位和状态卡片骨架；S2 前不伪造系统码表、短语或健康数据。
- 设置页通过左侧组内导航提供输入法、五笔行为、候选窗口、快捷键、外观、网络、数据、关于八组入口；S1 真实实现快捷键、外观、窗口/启动相关设置，其余使用规范占位。
- 码表、短语、反查、字根和学习页提供整页或区块占位，明确将提供的能力和所属阶段。
- 占位由 feature store 决定；已实现能力不得残留占位，未实现能力不得靠“点击后报错”表示。
- 首次运行引导只承担管理员权限、系统文件影响和备份保障的知情说明，不做营销页或教程轮播。

### 8. 质量与可访问性

- 全部用户文案外置到简体中文资源，预留其他 locale 接入点。
- Tab 顺序符合视觉顺序；所有交互都有可见焦点、语义角色和名称；弹层正确管理焦点和 `Esc` 退出。
- 颜色不是唯一信息载体；尊重 `prefers-reduced-motion` 和系统字号缩放。
- 冷启动到主窗口可交互不超过 2 秒，空闲 CPU 约为 0%，任何超过 100 ms 的工作异步执行。
- 保持既有 Rust、bindings、前端静态检查和测试门禁，并增加外壳相关 Rust、组件、路由、键盘和 Windows 集成测试。

## Out Of Scope

- S2 的真实码表/短语读取、列表、编辑、反查和系统状态数据接入。
- S3 的输入法启停、服务/计划任务控制、ACL 接管、系统文件写入、备份回滚和真实崩溃恢复。
- S4 及以后的编辑、变换、资源同步、自学习和输入采集。
- 安装器、签名、自动更新、Win10/ARM64 完整发布矩阵；S1 只保证架构和配置不阻断这些后续交付。
- ImTip 的页面、按钮、动作、托盘项、快捷键、配置、功能开关、进程探测、启动、URL 和依赖；`M7-WIN-005` 为永久 P3 禁止项，不进入任何后续阶段。
- 读取或转换根目录 `resource/` 中的任何文件。

## Acceptance Criteria

- [ ] `AC-S1-01` Release/开发应用均可启动；第二实例不创建新窗口，而是把首实例置前并转交合法参数。
- [ ] `AC-S1-02` 管理员声明和运行时权限检测一致；首次说明可访问，权限不足时显示明确恢复路径。
- [ ] `AC-S1-03` `/tray` 启动无主窗口闪现；托盘可以还原、置前和退出，退出后不残留图标或全局热键。
- [ ] `AC-S1-04` 无边框窗口控制完整；关闭策略、合法窗口 bounds、最大化状态、主题和密度在重启后保持，离屏 bounds 会自动纠正。
- [ ] `AC-S1-05` 配置首次创建、即时保存、schema 迁移、原子写入、写前备份、损坏回退和校验后导入/导出都有自动化测试；失败不覆盖最后一份有效配置。
- [ ] `AC-S1-06` 七个一级入口均可通过侧栏、`Ctrl+1..7`、命令面板和稳定深链接访问；浏览器式返回行为一致。
- [ ] `AC-S1-07` 应用页面和命令面板中的未实现领域显示规范占位及阶段徽标；最小托盘不展示未实现领域动作，任何占位都不可执行系统副作用。
- [ ] `AC-S1-08` 浅色、深色、跟随系统三种主题即时切换且首帧无闪白；两种密度不导致布局跳动；令牌和对比度检查通过。

- [ ] `AC-S1-12` 任务注册表支持进度、阶段、取消和互斥；状态栏非模态显示，取消或失败后相关控件恢复可用。
- [ ] `AC-S1-13` 错误详情、成功 toast、持久失败提示、空状态、确认、未保存拦截、拖放和首次知情说明均有键盘与可访问性覆盖。

## Risks And Deferred Items

- 整进程管理员权限扩大 WebView 和网络攻击面；S1 用严格 CSP、最小 Tauri capability 和无网络启动面约束，后续仍应演进到提权辅助进程。
- 当前窗口子任务的托盘菜单只有显示/退出，不需要动态刷新；完整领域菜单等统一动作目录和路由存在后再选择事件驱动投影，不为占位状态轮询系统。
- Tauri/WebView2 下主动清理工作集可能造成卡顿，`M7-WIN-009` 只做测量，不以牺牲空闲 CPU 或恢复速度为代价强行实现。
- Win10 1703、ARM64、WebView2 Bootstrapper、安装器与签名在发布阶段完成矩阵验收；S1 的 API 和配置必须保持兼容边界。
- `ui-ux-pro-max` 本机搜索脚本缺失；本规划使用该技能已加载的可访问性、主题、桌面工具和交互规则，并以仓库 `docs/21-ui-ux.md` 为产品视觉事实来源。
