## 1. 性能（`PERF`）

原项目的性能问题是重写的首要动因。以下指标以「海峰词库98（完整）」这类**数十万条目**的真实码表为基准。

| ID | 需求 | P | 指标 | 原项目现状 |
|---|---|---|---|---|
| `NFR-PERF-001` | 应用冷启动到主窗口可交互 | P0 | ≤ 2 s | 未测量；aardio 版本极快（786 KB） |
| `NFR-PERF-002` | 加载完整码表（含解析 + 建索引）到可浏览 | P0 | ≤ 5 s | **数分钟**，UI 完全冻结 |
| `NFR-PERF-003` | 码表表格滚动帧率 | P0 | ≥ 55 fps | 卡顿明显 |
| `NFR-PERF-004` | 单次反查（编码 + 拆字）响应 | P0 | ≤ 50 ms | 全表扫描，数百 ms |
| `NFR-PERF-005` | 编辑器内查找（数十万行） | P1 | ≤ 300 ms | 秒级 |
| `NFR-PERF-006` | 格式转换 / 精简（完整码表） | P1 | ≤ 3 s | 数十秒 |
| `NFR-PERF-007` | 词频重算（完整码表 + 数十万行词频文件） | P1 | ≤ 10 s | 数十秒 |
| `NFR-PERF-008` | 空码智能造词 | P1 | ≤ 60 s（并行） | 数分钟且不可取消 |
| `NFR-PERF-009` | 安装到系统码表（不含 TSF 停机等待） | P0 | ≤ 5 s | 数分钟 |
| `NFR-PERF-010` | 常驻内存（打开一份完整码表） | P1 | ≤ 300 MB | 未测量 |
| `NFR-PERF-011` | 空闲时 CPU 占用 | P0 | ≈ 0% | 满足 |
| `NFR-PERF-012` | **UI 线程永不阻塞**：任何 > 100 ms 的操作必须异步 | P0 | — | 原项目部分满足（用后台线程），但 UI 仍会冻结 |

| 预编译正则 | `once_cell::Lazy<Regex>`，避免逐行重编译 | `NFR-PERF-002` |

| `NFR-SEC-011` | 不在日志中记录用户输入内容、码表词条、短语内容 | P0 | |

| `NFR-SEC-013` | 依赖漏洞扫描纳入 CI（`cargo audit` / `npm audit`） | P1 | |
| `NFR-SEC-014` | 生成第三方依赖许可清单并在应用内展示 | P1 | 【原项目缺失】见 [`M5-ABOUT-008`](./modules/M5-etymon-help.md) |

### 演进目标

`NFR-SEC-001` 的整进程提权是**一期妥协**。二期应拆分为：

```
主进程（普通权限）
  ├── UI / 码表解析 / 网络 / 缓存
  └── IPC ──> 提权辅助进程（按需拉起，UAC 一次）
                ├── TSF 停机窗口
                ├── 文件 ACL 接管与系统码表写入
                └── HKLM 注册表写入
```

见 [`M7-INST-003`](./modules/M7-app-shell.md#m7-inst-003-管理员权限的取舍)。

## 3. 数据安全（`DATA`）

用户的**系统码表**与**自定义短语**是不可再生资产（短语尤其如此）。

| ID | 需求 | P | 说明 |
|---|---|---|---|
| `NFR-DATA-001` | 首次安装前备份「系统原始码表」，此备份**永不被覆盖** | P0 | 【原项目缺失】 |
| `NFR-DATA-002` | 每次写入系统码表/短语前，备份当前状态 | P0 | 【原项目缺失】 |
| `NFR-DATA-003` | 保留最近 N 份备份（默认 5），超出按时间淘汰 | P1 | |
| `NFR-DATA-004` | 写入后校验（魔数 + 条目数），失败自动回滚 | P0 | 【原项目缺失】 |
| `NFR-DATA-005` | 提供 UI 入口手动还原到任一备份或「系统原始码表」 | P1 | 【原项目缺失】 |
| `NFR-DATA-006` | 用户添加的码表存于**数据目录**，与可清理的缓存目录物理分离 | P0 | 【原项目缺失】原项目混放，清缓存会误删 |
