## 1. 设计立场

### 这是什么产品

一个**面向五笔使用者的专业配置工具**。用户特征：

- 技术亲和度高（愿意折腾码表的人不怕复杂界面）
- 重效率，讨厌等待
- 使用频率**低但关键** —— 装一次码表可能用一年，但装的时候不能出错
- 对「我的系统现在是什么状态」高度敏感

这决定了设计取向：**信息密度可以高，但状态必须清晰，破坏性操作必须可逆**。不是消费级产品的简化路线，也不是把 30 个功能塞进右键菜单的路线。

### 六条原则

| 原则 | 含义 | 违反的后果 |
|---|---|---|
| **状态先行** | 打开应用第一眼就知道「我现在装的是什么码表、健康吗、上次改了什么」 | 用户要点三层才能确认自己的配置 |
| **操作可见** | 功能出现在界面上，不藏在上下文菜单里 | 大部分功能永远不会被发现 |
| **永不冻结** | 任何操作都不阻塞界面；长任务有进度、有取消、可离开 | 用户以为程序卡死 |
| **可逆** | 破坏性操作前有备份，操作后可还原，操作中可中止 | 一次误操作毁掉用户积累 |
| **键盘优先** | 全部功能可键盘完成；命令面板是一等入口 | 专业用户被迫用鼠标 |
| **诚实** | 未实现的说未实现，失败的说清为什么，不确定的标不确定 | 用户对工具失去信任 |

### 与「现代化」的关系

「现代化」不等于圆角加大、留白加多、动效加满。本项目的现代化落在四个具体处：

1. **状态可视化** —— 用仪表盘替代「藏在列表项括号里的方案名」
2. **虚拟化** —— 数十万条数据流畅滚动，而非「请稍候数分钟」
3. **非模态** —— 长任务在后台跑，用户继续用别的页面
4. **可组合的键盘操作** —— 命令面板 + 全局可改绑快捷键

## 4. 视觉系统（`TOKEN`）

### 4.1 设计方向：墨

主色取自**书法笔墨**的深蓝黑。理由不是装饰性的：

- 领域是汉字输入，墨是这个领域最自然的视觉母题
- 深蓝黑在浅色底与深色底上都成立，不需要为两套主题挑两个不相干的主色
- 低饱和主色让**五区配色**和状态色有足够的表现空间 —— 这个产品里真正需要用颜色说话的是字根分区和操作状态，不是品牌

危险色取**朱砂**（朱批、印章），与墨形成传统语境下的自然对照。

> 这是一个有理由的起点，不是不可改的定论。若品牌另有要求，只需替换 `--color-primary` 与 `--color-danger` 两组变量，其余系统不受影响。

### 4.4 字体

| 用途 | 字体栈 |
|---|---|
| UI | `"Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif` |
| 等宽 | `"Cascadia Code", "JetBrains Mono", Consolas, monospace` |
| 字根 | `"WubiLexEtymon", "Cascadia Code", monospace` — PUA 字符依赖此栈首项 |

**规则**：

- 编码、码表条目、权重、日志一律等宽 —— 编码需要按位对齐才能一眼看出长度与差异
- 字根展示必须命中 PUA 字体，否则显示缺字符号（[`M3-FONT-003`](./modules/M3-reverse-lookup.md)）
- 汉字与拉丁字母混排时不做人为的字号差补偿，交给字体栈

### 4.5 五区配色

虚拟键盘的分区色**承载教学语义**（帮助记忆五笔笔画分区），是本产品少数「颜色即信息」的地方。

重新设计为 **5 个等距色相**，替代原项目随手挑的 pastel 组（那组在深色模式下完全不可用）：

| 区 | 笔画 | 键位 | 色相 | 浅色底 | 深色底 |
|---|---|---|---|---:|---|
| 1 区 | 横 | `G F D S A` | 45° 琥珀 | `#FDF0D5` | `#4A3A18` |
| 2 区 | 竖 | `H J K L M` | 120° 绿 | `#E4F3E2` | `#223A22` |
| 3 区 | 撇 | `T R E W Q` | 200° 蓝 | `#DFEEF7` | `#1B3441` |
| 4 区 | 捺 | `Y U I O P` | 275° 紫 | `#EBE6F7` | `#2E2842` |
| 5 区 | 折 | `N B V C X` | 345° 玫 | `#FBE6EC` | `#42232E` |
| — | 通配 | `Z` | — | 透明 | 透明 |

**约束**：

- 5 个色相在色轮上大致等距，最大化可辨识度
- 同区在两种主题下保持**同一色相**，只调明度与饱和度 —— 用户的记忆锚点是色相不是明度
- 颜色**不作为唯一区分手段**：每个键帽附区号角标（`UX-SCREEN-020`），满足 [`NFR-A11Y-004`](./20-nonfunctional.md)

### 4.6 Tailwind 约定

**版本定案：Tailwind CSS v4（CSS-first）** —— 见 [`02-architecture.md` §7 决策 D9](./02-architecture.md#7-关键设计决策)。

v4 取消了 JS 配置文件，令牌与变体全部写在 CSS 里。**项目中不存在 `tailwind.config.ts`**；令牌的单一事实来源是 `src/styles/theme.css`。

| 约定 | 说明 |
|---|---|
| 单一事实来源 | 令牌在 `src/styles/theme.css` 的 `@theme` 中定义一次，组件不写魔法值 |
| 构建接入 | Vite 插件 `@tailwindcss/vite`，无 `postcss.config.js` |
| 主题切换 | `@custom-variant dark (&:where(.dark, .dark *))`；跟随系统时由 JS 监听 `prefers-color-scheme` 同步 `<html>` 的 `dark` 类 |
| 语义色 | CSS 变量承载语义色，`@theme inline` 引用变量 → 同一套工具类在两主题自动取值 |
| 透明度 | 原生支持 `bg-primary/50`，不需要 v3 那种占位符语法 |
| 五区色 | 具名颜色 `wubi-zone-1` … `wubi-zone-5` |
| 组件层 | 复用样式用 `@layer components` 抽 `.btn-primary` 等，避免长类名在 JSX 中重复 |
| 密度 | `@custom-variant compact (&:where([data-density="compact"], [data-density="compact"] *))` 覆盖行高与内边距 |
| 类名排序 | `prettier-plugin-tailwindcss`，配置项用 `tailwindStylesheet: "./src/styles/theme.css"` |

**`@theme inline` 是深浅色能生效的前提**。不带 `inline` 的 `@theme` 会把变量的**值**烘死进生成的工具类；加 `inline` 后工具类在**使用处**解析变量，切换 `.dark` 才能改变已渲染元素的取色。这一处写错的表现是「主题切换按钮点了没反应」，且很难从现象反推原因。

```css
/* src/styles/theme.css */
@import "tailwindcss";

@custom-variant dark    (&:where(.dark, .dark *));
@custom-variant compact (&:where([data-density="compact"], [data-density="compact"] *));

@theme inline {
  --color-primary:     var(--wl-primary);
  --color-surface-1:   var(--wl-surface-1);
  --color-surface-2:   var(--wl-surface-2);
  --color-wubi-zone-1: var(--wl-zone-1);   /* 横 GFDSA */
  --color-wubi-zone-2: var(--wl-zone-2);   /* 竖 HJKLM */
  --color-wubi-zone-3: var(--wl-zone-3);   /* 撇 TREWQ */
  --color-wubi-zone-4: var(--wl-zone-4);   /* 捺 YUIOP */
  --color-wubi-zone-5: var(--wl-zone-5);   /* 折 NBVCX */

  --font-mono:   "Cascadia Code", "JetBrains Mono", Consolas, monospace;
  --font-etymon: "WubiLexEtymon", "Cascadia Code", monospace;
}

:root {
  --wl-primary:   #1E3A5F;
  --wl-surface-1: #FFFFFF;
  --wl-surface-2: #F7F8FA;
  /* 其余取 §4.3 色板的「浅色」列、§4.5 五区配色的浅色组 */

  --wl-duration-fast: 120ms;   /* UX-TOKEN-008 */
  --wl-duration-base: 200ms;
}

.dark {
  --wl-primary:   #7DA7D9;
  --wl-surface-1: #16191D;
  --wl-surface-2: #1D2126;
  /* 其余取 §4.3 色板的「深色」列、§4.5 五区配色的深色组 */
}
```

|---|---|

### 6.1 占位状态规范

外壳与导航在 [阶段 S1](./22-roadmap.md) 就完成，此时大部分功能模块尚未实现。**入口必须可见** —— 让产品的完整形状立刻可评审，同时诚实标注哪些还没做。

| 层级 | 呈现 |
|---|---|
| **整页未实现** | 页面中央占位卡：图标 + 「功能暂未完善」+ 一句话说明该页将提供什么 + 阶段徽标 |
| **页内区块未实现** | 区块内联占位条，样式弱于正常内容，不抢视觉 |
| **单个操作未实现** | 按钮/菜单项**保留可见但禁用**，悬停提示「功能暂未完善」 |
| **导航项未实现** | 导航项正常显示，附小圆点或「开发中」角标 |

**规则**：

1. 占位文案统一为「功能暂未完善」，不混用「敬请期待」「Coming Soon」
2. 每处占位**必须说明该功能将做什么** —— 只写「暂未完善」等于没说
3. 占位不得是空白页或死链
4. 占位由**构建期特性开关**驱动，功能就绪即自动切换，不留手工清理的债
5. 已实现的功能**不得**残留占位
