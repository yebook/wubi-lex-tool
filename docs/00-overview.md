# 00 — 项目总览

## 1. 背景

**WubiLex（五笔助手）** 是一个用 [aardio](http://www.aardio.com/) 编写的 Windows 桌面工具，开源地址 <https://github.com/aardio/wubi-lex>，当前分析版本 **v12.1**，编译产物体积约 786 KB。

它解决的核心问题是：**Windows 自带的微软五笔输入法码表陈旧、词库贫乏、且不提供任何官方的码表替换手段**。WubiLex 通过直接接管系统文件 `%WINDIR%\InputMethod\CHS\ChsWubi.lex` / `ChsWubiNew.lex` 与用户短语库 `%APPDATA%\Microsoft\InputMethod\Chs\ChsWubiEUDPv1/v2.lex`，实现了码表与短语的自由替换。

围绕这条主链路，它还长出了一批配套能力：反查拆字（含笔顺动画与虚拟键盘）、字根图库、输入法开关与双拼方案管理、微软五笔注册表设置的图形化封装。

### 原项目现状

| 指标 | 值 |
|---|---|
| 源文件 | 32 个 `.aardio` |
| 代码行数 | 7,574 行 |
| 最大单文件 | `dlg/dict/lex.aardio`（1,455 行）、`lib/wubi/lexFile.aardio`（1,406 行） |
| 内置码表方案 | 五笔 86 / 98 / 新世纪(06) / 091 / 092 / 郑码 / 小鹤音形 / 表形码 |
| 在线码表条目 | 40+ 条，分 8 大类 |
| UI 框架 | aardio `win.ui`，Win32 原生控件 + 自绘 `plus` 控件 |
| 权限要求 | 管理员（`//RUNAS//`） |
| 在线资源 | 全部指向 `http://wubi.aardio.com`（**明文 HTTP**） |

### 原项目的结构性问题

这些问题是重写的直接动因。**新项目不继承原项目的任何实现方式** —— 见 [`02-architecture.md#0`](./02-architecture.md#0-首要原则旧项目是行为规格不是实现范本)：旧项目只作为**行为规格**，实现方式一律取更优解。

1. **UI 与业务逻辑深度耦合**。核心业务逻辑（造词、格式转换、精简）直接写在 `dlg/dict/lex.aardio` 的菜单回调里，无法被测试或复用。
2. **超大文本框作为主编辑器**。完整码表可达数十万条目，全部塞进一个 Win32 `edit` 控件，加载时 UI 冻结数分钟，且靠 `busy()` 动画掩盖。
3. **无错误恢复**。安装到系统码表失败时提示「请重试一次即可」——ACL 接管与服务重启的中间态没有回滚机制。
4. **资源单点依赖**。所有码表、字根图、笔顺 GIF、字体、词频文件都从单一 HTTP 服务器拉取，无镜像、无校验、无 HTTPS。
5. **死代码残留**。超级热键模块（303 行）已被 README 声明废弃但仍在仓库中；另有 3 个 `@Deprecated` 别名文件。
6. **界面无状态层**。用户打开应用看不到「我现在装的是什么码表、健康吗」，这个信息藏在列表首项的括号里。

## 2. 新项目目标

**项目名：WubiLexTool** · 技术栈 Rust + Tauri 2 + React 19 + Tailwind CSS v4 · Windows 独占。

| 目标 | 说明 |
|---|---|
| **功能对等** | 覆盖原项目全部在用功能（P0/P1/P2），废弃项显式排除 |
| **逻辑可测** | 码表/短语的解析、变换、编解码沉入纯 Rust crate，脱离 UI 可单测 |
| **界面现代化** | 全新 UI（React 19 + Tailwind v4 + Lucide），深浅色主题、响应式布局、非阻塞长任务、键盘可达 |
| **大数据可用** | 数十万条码表的加载、编辑、搜索在秒级完成，UI 不冻结 |
| **操作可回滚** | 系统码表/短语的写入具备备份与还原能力 |
| **资源可控** | 在线资源升级 HTTPS，加校验，支持自建镜像 |
| **快捷键可定制** | 统一的动作注册表，全部快捷键可改绑（原项目仅支持改 1 个） |
| **能自我成长** | 自学习模块，把用户高频使用的新词自动补入词库 |

### 非目标

- 跨平台（macOS / Linux）——本项目 **Windows 独占**
- 实现一个输入法引擎（本项目只管理微软五笔，不替代它）
- 超级热键 / 全局按键改键，以及任何 ImTip 集成或推广

### 模块职责边界

| 模块 | 职责 | 明确不做 |
|---|---|---|
| **M1** 码表管理 | 码表的读取、解析、编辑、变换、写入系统 | 不直接操作 TSF/服务（委托 M4）、不做网络下载（委托 M6） |
| **M2** 短语词库 | 短语的读取、解析、编辑、写入系统 | 同上 |
| **M3** 反查拆字 | 由汉字/词组反查编码与字根拆分，可视化呈现 | 不修改任何系统状态，只读 |
| **M4** 输入法控制 | 输入法启停、双拼、注册表设置、TSF 服务重启与 ACL 接管 | 不理解码表内容，只负责「安全地替换文件并重启输入法」 |
| **M5** 字根与帮助 | 静态资料的展示 | 无业务逻辑 |
| **M6** 资源分发 | 在线目录、下载、解压、本地缓存、软件自更新 | 不解析下载内容（交给 M1/M2/M3） |
| **M7** 应用外壳 | 进程与窗口生命周期、快捷键映射、配置持久化、模块间事件分发 | 不含任何领域逻辑 |
| **M8** 自学习 | 从语料或实际输入中发现新词，自动补入词库 | 不直接写系统文件（经 M2 走短语库）；**整体 P2 后置** |

## 5. 术语表

### 五笔与输入法领域

| 术语 | 含义 |
|---|---|
| **码表 / Lex** | 编码到汉字/词组的映射表。微软五笔的二进制格式为 `.lex`（魔数 `imscwubi`） |
| **编码 / Code** | 一串 1–4 位小写字母，对应键盘按键序列。如「王」= `ggg` |
| **词条 / Word** | 编码对应的输出文本，可以是单字或词组 |
| **重码** | 同一编码对应多个词条的情况。重码数是衡量码表质量的关键指标 |
| **权重 / Weight** | 决定同一编码下候选词排序的数值，**越小越靠前**，取值 1–65535 |
| **简码** | 用少于全码长度的编码输入常用字。一级简码 = 单个字母，如 `g` = 「一」 |
| **全码** | 完整的 4 位编码 |
| **出简不出全** | 一个字有简码时，删除其全码条目，避免重复占位 |
| **出简后出全** | 保留全码但把它排在简码字之后（`optShortCodeChar`） |
| **键名字** | 编码为 `aaaa`–`yyyy`（同一字母重复 4 次）的字，五笔中是各键位的代表字 |
| **Z 键通配** | 微软五笔中 `z` 可通配任意编码（首码除外）。含 `z` 的编码在码表中无效，只能放短语库 |
| **短语 / EUDP** | 用户自定义短语词库，End User Defined Phrase。文件 `ChsWubiEUDPv1/v2.lex`（魔数 `mschxudp`） |
| **字根 / Etymon** | 五笔拆字的基本部件。每个字母键对应一组字根 |
| **字根歌诀** | 帮助记忆字根分布的口诀，如 86 版 `G 王旁青头戋（兼）五一` |
| **拆字** | 把一个汉字分解为字根序列的过程 |
| **反查** | 由汉字/词组反向查出其五笔编码 |
| **形码拼音混输** | 微软五笔允许同时用拼音输入的模式（注册表 `PinyinMixEnable`） |
| **四码唯一自动上屏** | 输入满 4 码且只有唯一候选时直接上屏，无需按空格 |
| **双拼** | 用两个按键表示一个拼音音节的方案。微软拼音支持内置与自定义方案 |

### 码表方案

| 代号 | 名称 | 特征 |
|---|---|---|
| `86` | 五笔 86 版 | 最广泛使用的传统方案 |
| `98` | 五笔 98 版 | 王码 98 规范 |
| `06` | 五笔新世纪 | 又称 06 版 |
| `091` | 五笔 091 | 点儿 091 方案 |
| `092` | 五笔 092 | 需专用字根字体 |
| `zhengma` | 郑码 | 非五笔系形码，造词规则不同 |
| `xhyx` | 小鹤音形 | 音形混合，强制开启拼音混输 |
| `bxm` | 表形码 | 非五笔系形码，造词规则不同 |

### Windows 技术

| 术语 | 含义 |
|---|---|
| **TSF** | Text Services Framework，Windows 的输入法框架 |
| **TIP** | Text Input Processor，TSF 下的一个输入法实例 |
| **ctfmon.exe** | TSF 的宿主进程 |
| **ChsIME.exe** | 微软中文输入法进程 |
| **MsCtfMonitor** | 计划任务 `\Microsoft\Windows\TextServicesFramework\MsCtfMonitor`，负责拉起 ctfmon |
| **TabletInputService** | 触摸键盘和手写面板服务，会持有输入法文件句柄 |
| **TrustedInstaller** | 系统文件的默认所有者，普通管理员也无法直接修改其拥有的文件 |
| **ICACLS** | Windows 命令行 ACL 管理工具 |
| **微软五笔 TIP GUID** | CLSID `{6A498709-E00B-4C45-A018-8F9E4081AE40}` / Profile `{82590C13-F4DD-44F4-BA1D-8667246FDF8E}`，语言 ID `0x804` |
| **微软拼音 TIP GUID** | CLSID `{81D4E9C9-1D3B-41BC-9E6C-4B40BF79E35E}` / Profile `{FA550B04-5AD7-411F-A5AC-CA038EC515D7}` |

### 本文档约定

| 术语 | 含义 |
|---|---|
| **系统码表** | 当前生效的 `%WINDIR%\InputMethod\CHS\ChsWubiNew.lex`（不存在则 `ChsWubi.lex`） |
| **用户码表** | 用户在应用内添加/保存的码表，存于 `%APPDATA%` 下的应用目录 |
| **安装** | 把某个码表写入系统码表位置并重启输入法使其生效 |
| **追加** | 把某个码表**合并**进现有系统码表，而非替换 |

```
├── spelling\{ver}\               笔顺动画 GIF
├── spelling-data-table\v2\       拆字数据表 (*.txt)
├── fonts\                        字根字体 (*.otf)
├── download\                     下载暂存
├── word-weight2.txt              微软词频文件
└── lex-default-v2.table          在线码表目录缓存

%APPDATA%\aardio\std\wubi-lex-tool\   应用配置
```

**新项目（WubiLexTool）的目录规划**：

```
%LOCALAPPDATA%\WubiLexTool\
├── cache\                        可清理：下载的资源
│   ├── lex\ etymon\ stroke\ split-table\ fonts\
├── data\                         用户数据：不可清理
│   ├── lex\                      用户添加的码表
│   ├── backup\                   系统码表/短语备份
│   └── learn\                    M8 自学习数据（加密）
└── logs\

%APPDATA%\WubiLexTool\
└── config\                       配置与快捷键绑定
```

> **关键区分**：用户添加的码表是**数据**不是缓存。原项目把二者混放在 `wubi/lex/`，清理缓存会误删用户数据（见 [`M6-CACHE-006`](./modules/M6-resource-sync.md)）。

## 7. 优先级定义

| 级别 | 判据 | 覆盖范围 |
|---|---|---|
| **P0** | 缺失则产品不成立 | 码表解析/编辑/安装主链路、短语读写、反查基础查询、输入法启停、应用外壳最小闭环 |
| **P1** | 显著影响体验，可延后到 v1.1 | 格式转换、精简、词频优化、造词、笔顺动画、字根图、双拼、在线目录 |
| **P2** | 锦上添花，或依赖外部不可控资源 | 手写输入、语音输入、第三方联想 API、Windows 技巧文本、鼠标左右键反转 |
| **P3** | **不实现**，仅历史记录 | ImTip 集成、超级热键模块、3 个 `@Deprecated` 别名文件、候选窗口探测 |
