> **模块职责**：五笔码表的读取、解析、编辑、变换、优化、造词与写入系统。
> 这是全项目**体量最大、价值最高**的模块，对应原项目 3,365 行代码（占总量 44%）。

### 详述：条目存储模型

原项目用两个平行结构维护列表，新实现应改为单一有序数组：

```rust
struct LexEntry {
    name: String,              // 用户指定的友好名称，唯一
    source: LexSource,         // 本地路径 或 远程 URL
    cached_path: Option<PathBuf>,
}

enum LexSource {
    Local(PathBuf),
    Remote(Url),               // 下载后填充 cached_path
}
```

本地缓存路径规则：`<AppData>/lex/<name>.lex`

`M1-PARSE-017`（`spelling`）在原项目中是 **O(编码数 × 词条数)** 的全表线性扫描（`lexFile.aardio:454-466`）。完整码表下每次反查耗时可达数百毫秒，在 M3 的实时输入场景中会明显卡顿。

### 详述：`M1-EDIT-002` 大数据量编辑

**问题**：完整五笔码表（如「海峰词库98」）可达 **数十万条目 / 数 MB 文本**。原项目把全部内容塞进单个 Win32 `edit` 控件，导致：

- 加载耗时数分钟，UI 完全冻结（原项目提示「可能需要数分钟」）
- 内存占用高
- 查找/滚动迟滞

**新实现方案（三选一，建议 B）**：

| 方案 | 描述 | 代价 |
|---|---|---|
| A. 虚拟化文本编辑器 | CodeMirror 6 / Monaco，仅渲染视口内行 | 需自定义语法高亮与大文档模式调优 |
| **B. 表格视图 + 局部文本编辑（建议）** | 主视图用虚拟滚动表格（编码 / 词条 / 权重 三列），支持排序筛选；仅在需要时对单条进入编辑 | 与原项目的「纯文本编辑」心智模型不同，需在 UI 上补「切换到文本模式」 |
| C. 分页文本编辑 | 按字母分段加载 | 跨段操作（如全局转换）体验割裂 |

无论哪种方案，**转换/精简/词频/造词等批量操作必须在 Rust 侧对内存模型执行**，不得往返序列化为文本。原项目每次操作都做「文本 → 解析 → 变换 → 序列化 → 文本」的全量往返，这是其卡顿的根因。

### 详述：`M1-WEIGHT-007` 出简后出全

**场景**：五笔中常用字有简码（如「一」= `g`），同时也有全码（`ggll`）。若全码下「一」排在第一位，用户打全码时会先出「一」，但「一」用简码更快 —— 全码首位应让给其他字。

**算法**（`lexFile.aardio:680-717`）：

1. 扫描所有**长度 < 4** 的编码，记录其首候选单字及该简码长度 → `shortCodeMap[字] = 码长`
2. 对每个**长度 == 4** 且候选数 ≥ 2 的编码：
   - 设首候选 `txt`、次候选 `txt2`
   - 若 `txt` 在 `shortCodeMap` 中：
     - 若 `txt2` 也在 `shortCodeMap` 中 **且** `txt` 的简码长度 ≠ 3 → 跳过（避免把另一个简码字换上来）
     - 否则交换 `txt` 与 `txt2`，并把 `txt` 的权重设为 `txt2` 权重 + 1
3. 返回交换次数

| `M1-COIN-005` | **空码智能造词**：遍历词频库，对码表中空闲（候选 < 2）的编码位补入流行词 | P1 | `lex.aardio:803-907` | 号称可新增十余万词；**耗时数分钟**，必须可取消 + 进度反馈 |
| `M1-COIN-006` | 构建「单字 → 最长编码」缓存以加速造词，支持失效重建 | P1 | `lexFile.aardio:1079-1101` | |
| `M1-COIN-007` | 造词前校验源码表非空，为空则提示并中止 | P1 | `lex.aardio:749-753` | |

### 详述：三种造词规则对比

记 `C[i][j]` 为第 `i` 个字编码的第 `j` 位。缺失任一字的编码则整词造词失败。

| 词长 | 五笔 (`combine`) | 郑码 (`combineZhengma`) | 表形码 (`combineBxm`) |
|---|---|---|---|
| 2 字 | `C1[1] C1[2] C2[1] C2[2]` | `C1[1] C1[2] C2[1] C2[2]` | `C1[1] C1[2] C2[1] C2[2]` |
| 3 字 | `C1[1] C2[1] C3[1] C3[2]` | `C1[1] C2[1] C2[2] C3[1]` | `C1[1] C1[2] C2[1] C3[1]` |
| ≥4 字 | `C1[1] C2[1] C3[1] C末[1]` | `C1[1] C2[1] C3[1] C4[1]` | `C1[1] C2[1] C3[1] C末[1]` |

> 注意 ≥4 字时：五笔与表形码取**末字**，郑码取**第 4 字**（`lexFile.aardio:1151-1153` vs `1119-1122`）。这是原项目的实际行为，新实现应保持一致。

### 详述：`M1-COIN-005` 空码智能造词

```
输入：源码表 L（提供单字编码）、目标码表 T（编辑器当前内容）、词频文件 W
输出：T 中新增的词条

for (word, weight) in W:
    if 字符数(word) == 1: 跳过
    code = 按方案规则造词(L, word)
    if code 为空: 跳过
    if T 中 code 的候选数 >= 2: 跳过          // 该编码位已满，不占用
    收集 newWord[code] += (word, weight)

for code in newWord:
    按 weight 升序排序
    只取权重最小的一个词加入 T
```

词频文件可达数十万行，逐行造词 + 查表是重计算。**必须**：

- 在后台线程执行，`rayon` 并行分片
- 提供进度百分比与取消
- 结果提示新增条数（原项目：「已添加空码新词：N 个」）

## 8. 短语分离（`SPLIT`）

微软五笔的码表**不能**包含两类词条，它们只能放在用户短语库（EUDP）中：

1. 含 `z` 键的编码（`z` 是通配键）
2. 占用键名编码（`aaaa`–`yyyy`）的非常用单字

| ID | 需求 | P | 来源 | 备注 |
|---|---|---|---|---|
| `M1-SPLIT-001` | 检测码表是否含上述两类词条，返回位标志（bit0 = 含 z 键，bit1 = 键名占用） | P0 | `lexFile.aardio:740-787` | 安装前置检查 |
| `M1-SPLIT-002` | 分离 z 键编码与键名非常用单字词条，从码表移除并输出为短语文本 | P0 | `lexFile.aardio:788-856` | 输出格式 `code=词\r\n` |
| `M1-SPLIT-003` | 分离与**当前系统短语库**编码冲突的词条 | P1 | `lexFile.aardio:857-888`、`lex.aardio:952-980` | 避免候选排序错乱 |
| `M1-SPLIT-004` | 分离结果提供「另存为 `.phrase.txt`」，无冲突时提示「未包含…」 | P1 | `lex.aardio:969-976, 997-1004` | |

### 详述：键名占用的判定规则

对每个键名编码 `aaaa`–`yyyy`（注意**不含 `zzzz`**），统计其候选词条：

```
gb   = GB2312 单字数量
rare = 出现在多字词之后的非 GB2312 单字数量
hasWord = 是否出现过多字词

判定为「键名被非常用单字占用」当且仅当：
    (gb > 0 且 (gb + rare) > 4 且 候选总数 >= 9)
  或 (gb == 0 且 rare > 0)
```

来源 `lexFile.aardio:754-783`。

> **这是行为契约 `C8`**（见 [`02-architecture.md#0.1`](../02-architecture.md#01-什么必须一致行为契约)）。规则本身是拍脑袋的经验判据，质量不高 —— 保留它**不是因为实现好，而是因为它的输出定义了「哪些词条能进码表」**。判错会让词条进错位置，导致系统候选排序异常。
>
> 做法：判定逻辑逐位实现 + 代码注释标明其经验性质 + 单元测试固化行为。实现方式（数据结构、遍历顺序）自由。

### 详述：`M1-INSTALL-013` 备份与回滚（新增需求）

**问题**：原项目的安装流程存在多个不可恢复的中间态：

```
停服务 → 结束计划任务 → kill 进程 → 接管 ACL → 删除原文件 → 写入新文件 → 还原 ACL → 恢复服务
                                                    ↑
                                    在此处失败 = 系统码表丢失，五笔完全不可用
```

且原项目在删除失败时会**循环重试 10 次**（`tsfUtil.aardio:138-147`），每次 sleep 1 秒，之后**不检查是否成功就继续**。

**新实现要求**：

1. 首次安装前，把原始 `ChsWubi*.lex` 完整备份到 `<AppData>/backup/original/`，标记为「系统原始码表」，**永不覆盖**
2. 每次安装前，把当前系统码表备份到 `<AppData>/backup/last.lex`
3. 写入失败或校验失败时，自动从 `last.lex` 回滚
4. 提供 UI 入口手动还原到「系统原始码表」
5. 写入后校验：重新读取并比对魔数与条目数

TSF 重启流程与 ACL 接管的完整需求见 [M4](./M4-ime-control.md)。
