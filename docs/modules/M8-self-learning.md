# M8 — 自学习造词

> **模块职责**：观察用户的实际用字用词，把码表中缺失的高频新词自动补入词库。
>
> **原项目无此功能** —— 本模块 100% 为新增设计。
>
> **整体优先级 P2**（用户明确要求后置）。但一旦启动本模块开发，其内部 `PRIV` 域即为该模块的准入前提，不可裁剪。

## 1. 问题与场景

五笔的固有痛点：**新词跟不上**。

```
「黑神话」——  码表里没有
用户每次都要拆成「黑」「神」「话」三个字打
打了几十次之后，它依然不在码表里
```

原项目的对应能力是 [`M1-COIN-005` 空码智能造词](./M1-lex-table.md#详述m1-coin-005-空码智能造词) —— 拿一份**静态的**微软词频文件去补空码位。它解决的是「通用流行词」，解决不了**你个人的**高频词（专有名词、行业术语、人名、项目代号）。

M8 补的正是这一块：**从你实际打的字里学**。

## 2. 两条路径

本模块提供两条技术路径，隐私风险与覆盖面成反比。

| 路径 | 数据来源 | 隐私风险 | 覆盖面 | 建议 |
|---|---|---|---|---|
| **A. 语料导入**（`CORPUS`） | 用户主动提供的文本 | **无** | 取决于用户提供什么 | ✅ **先做这条** |
| **B. 输入采集**（`CAPTURE`） | 后台观察实际上屏内容 | **高** | 全覆盖 | ⚠️ 默认关闭，显式授权 |

两条路径**共用** `LEARN` / `APPLY` / `MANAGE` 三个下游域。

```
┌─ A. 语料导入 ─┐
│ 粘贴 / 导入文件 │──┐
└───────────────┘  │   ┌──────────┐   ┌──────────┐   ┌──────────┐
                    ├──▶│  LEARN   │──▶│  APPLY   │──▶│  MANAGE  │
┌─ B. 输入采集 ─┐  │   │ 分词/计数 │   │ 造码/入库 │   │ 管理/导出 │
│ 后台观察上屏   │──┘   └──────────┘   └──────────┘   └──────────┘
└───────────────┘
        ▲
   PRIV 隐私控制（默认关闭 · 显式授权 · 本地加密 · 一键清除）
```

## 3. 路径 A：语料导入（`CORPUS`）

**零隐私风险**，用户完全控制输入什么。建议作为 M8 的第一阶段交付。

| ID | 需求 | P | 备注 |
|---|---|---|---|
| `M8-CORPUS-001` | 支持粘贴文本或导入文件作为语料（`.txt` / `.md` / `.csv`，UTF-8/UTF-16/GBK 自动识别） | P2 | 复用 [`M1-PARSE-003`](./M1-lex-table.md) 的编码探测 |
| `M8-CORPUS-002` | 支持批量导入目录下的多个文件 | P2 | 常见场景：导出的聊天记录、笔记目录、代码注释 |
| `M8-CORPUS-003` | 展示语料统计：字数、句数、识别出的候选新词数 | P2 | |
| `M8-CORPUS-004` | 生成候选后进入**预览表**（词 / 频次 / 生成的编码 / 该编码当前占用情况），用户勾选后入库 | P2 | 不自动入库，避免污染词库 |
| `M8-CORPUS-005` | 语料在提取完成后**立即丢弃**，不落盘 | P2 | 只保留分词结果与计数 |

## 4. 路径 B：输入采集（`CAPTURE`）

**默认关闭。** 需用户在设置中显式开启并通过隐私确认。

| ID | 需求 | P | 备注 |
|---|---|---|---|
| `M8-CAPTURE-001` | 采集用户已上屏的中文文本 | P2 | 技术方案见 [§4.1](#41-采集方案对比) |
| `M8-CAPTURE-002` | 仅在中文输入法处于激活状态时采集 | P2 | 英文输入、纯粘贴内容不采集 |
| `M8-CAPTURE-003` | **密码类输入框绝不采集** | P2 | 检测 `ES_PASSWORD` 样式 / UIA `IsPassword` 属性 |
| `M8-CAPTURE-004` | 支持进程黑名单，默认包含常见密码管理器、银行客户端、终端 | P2 | 用户可增删 |
| `M8-CAPTURE-005` | 支持窗口标题关键词黑名单（如含「密码」「登录」「支付」） | P2 | |
| `M8-CAPTURE-006` | 采集在独立后台任务中执行，对输入延迟的影响 < 1 ms | P2 | 绝不能拖慢打字 |

### 4.1 采集方案对比

Windows 上没有「订阅所有上屏文本」的公开 API。可选方案各有明显短板：

| 方案 | 原理 | 覆盖面 | 复杂度 | 风险 |
|---|---|---|---|---|
| **UI Automation TextPattern** | 监听焦点元素的 `TextChanged` 事件，diff 出新增文本 | 中（依赖应用是否实现 UIA Text） | 中 | 部分应用（游戏、Electron 旧版、部分 IDE）不支持 |
| **TSF `ITfTextEditSink`** | 注册文本编辑接收器，监听编辑会话 | 高 | **高** | 需实现 TSF 组件并注入目标进程，等同写半个输入法 |
| 低级键盘钩子 | 捕获按键序列，反推上屏内容 | 低 | 中 | 五笔上屏的是候选词不是按键，**无法可靠还原** |
| 剪贴板监听 | 捕获复制内容 | 极低 | 低 | 只能拿到用户复制的东西，不是输入的东西 |
| 读微软 IME 学习数据 | 直接读 IME 自身的自学习存储 | — | — | **格式未公开**，且形码部分很可能不存在此数据 |

**建议**：采用 **UI Automation TextPattern**，接受覆盖面不完整。它是唯一「复杂度可控 + 不需要注入进程 + 语义正确」的方案。

在文档中明确告知用户：*采集是尽力而为的，部分应用中的输入不会被学习。*

> **明确不做**：低级键盘钩子。原项目的超级热键模块（[`M7-DEPR-001`](./M7-app-shell.md#8-已废弃模块p3)）用过这个机制，其注释里就写着「耗时超过一秒系统会直接删除键盘钩子」。用它做文本还原既不可靠又有性能风险。

## 5. 学习（`LEARN`）

两条路径的共用下游。

| ID | 需求 | P | 备注 |
|---|---|---|---|
| `M8-LEARN-001` | 对文本做中文分词，提取候选词 | P2 | 见 [§5.1](#51-分词方案) |
| `M8-LEARN-002` | 维护候选词的频次计数与最近出现时间 | P2 | |
| `M8-LEARN-003` | 过滤已存在于系统码表或短语库中的词 | P2 | 依赖 [`M1-PARSE-017`](./M1-lex-table.md)、[`M2-IO-008`](./M2-phrase.md) |
| `M8-LEARN-004` | 过滤不合规候选：长度越界（默认 2–6 字）、含非汉字、纯数字、常见停用词 | P2 | 阈值可配 |
| `M8-LEARN-005` | 升为「待入库候选」需同时满足：频次 ≥ 阈值（默认 5）**且**跨 ≥ 2 个会话出现 | P2 | 跨会话条件用于排除一次性误采 |
| `M8-LEARN-006` | 时间衰减：超过 N 天（默认 90）未再出现的候选自动淘汰 | P2 | 防止候选池无限膨胀 |

### 5.1 分词方案

| 方案 | 说明 | 评估 |
|---|---|---|
| **`jieba-rs`** | 结巴分词的 Rust 移植，词典约 5 MB | ✅ 推荐。成熟、纯 Rust、支持自定义词典 |
| N-gram 统计 | 不分词，直接统计 2–6 字连续片段，按互信息/左右熵筛选 | 适合**发现词典里没有的新词**（正是本模块的目标），可作为 jieba 的补充 |
| 调用系统分词 API | Windows 有 `IWordBreaker` | 覆盖面与质量不确定，不建议 |

**建议组合**：jieba 做基础切分 → 对切分结果中相邻的「未登录词」片段做 N-gram 合并 → 用互信息（PMI）与左右信息熵过滤。这正是新词发现的标准做法，也恰好命中「黑神话」这类词典外专名。

## 6. 入库（`APPLY`）

| ID | 需求 | P | 备注 |
|---|---|---|---|
| `M8-APPLY-001` | 用当前码表方案的造词规则为候选词生成编码 | P2 | 复用 [`M1-COIN-001/002/003`](./M1-lex-table.md#7-造词coin) |
| `M8-APPLY-002` | 仅在目标编码位空闲（现有候选 < 2）时入库，不挤占常用字 | P2 | 与 `M1-COIN-005` 同策略 |
| `M8-APPLY-003` | 两种入库模式：**提示确认后入库**（默认）/ 自动入库 | P2 | 默认不自动改词库 |
| `M8-APPLY-004` | **入库走短语库（EUDP）而非系统码表** | P2 | 见下方说明 |
| `M8-APPLY-005` | 批量入库：累积到 N 条或按周期触发，一次性写入 | P2 | 避免频繁写入 |
| `M8-APPLY-006` | 入库前备份现有短语库，失败自动回滚 | P2 | 复用 [`M2-INSTALL-010`](./M2-phrase.md) |

### 为什么走短语库而不是系统码表

| 维度 | 写系统码表 | 写短语库（EUDP） |
|---|---|---|
| 是否需要停机窗口 | **需要**（停服务、kill 进程、ACL 接管） | 不需要 |
| 单次写入耗时 | 数分钟 | 秒级 |
| 失败影响面 | 输入法可能完全不可用 | 短语丢失，输入法仍可用 |
| 用户可感知的中断 | 输入法重启 | 无 |
| 容量 | 数十万条 | 数百至数千条（足够个人新词） |

自学习是**持续、高频、低量**的写入，短语库是唯一合适的载体。系统码表的写入代价见 [`M4-TSF-*`](./M4-ime-control.md#5-tsf-重启与-acl-接管tsf)。

> **副作用提示**：写短语库会触发 `Enable Wubi EUDP = 1`（[`M4-REG-004`](./M4-ime-control.md)）。若用户此前关闭了自定义短语，需在开启 M8 时告知。

## 8. 隐私控制（`PRIV`）

> **本域是路径 B 的准入前提。** 若不实现 `PRIV-001..005`，则不得实现 `CAPTURE-*`。

| ID | 需求 | P | 备注 |
|---|---|---|---|
| `M8-PRIV-001` | 输入采集**默认关闭**；首次开启时展示明确的隐私说明页并要求用户主动确认 | P2 | 说明必须直白：「本功能会记录你在其他应用中输入的中文内容」 |
| `M8-PRIV-002` | 提供全局开关与「暂停 30 分钟 / 1 小时 / 至重启」快捷入口 | P2 | 托盘菜单可直达 |
| `M8-PRIV-003` | 采集数据仅存本地并加密；**永不上传** | P2 | 与 [`NFR-PRIV-006`](../20-nonfunctional.md) 呼应 |
| `M8-PRIV-004` | **不保存原始文本**，只保留分词后的词条与计数 | P2 | 采集 → 分词 → 计数 → 立即丢弃原文 |
| `M8-PRIV-005` | 提供一键清除全部自学习数据（含候选池、计数、已入库记录） | P2 | |

### 数据留存边界

```
上屏文本  "今天玩了黑神话，боss 很难"
    │
    ├─ 分词 ─▶  [今天] [玩] [黑神话] [боss] [很难]
    │
    ├─ 过滤 ─▶  [黑神话]        （已在词库/含非汉字/长度越界的丢弃）
    │
    ├─ 计数 ─▶  黑神话: 1 次, 首见 2026-08-21, 会话 #47
    │
    └─ 原文 ─▶  ✗ 立即丢弃，不落盘、不入日志
```

## 13. 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 输入采集的隐私影响（记录用户在所有应用中的输入） | **极高** | 默认关闭 + 显式授权 + 只存分词结果 + 本地加密 + 一键清除，见 `M8-PRIV-*`。**先只做路径 A** |
| 密码/敏感内容被误采 | **极高** | 密码框检测 + 进程黑名单 + 标题黑名单，见 `M8-CAPTURE-003/004/005` |
| UIA 采集覆盖面不完整，用户预期落空 | 中 | 文档与 UI 明示「尽力而为」，管理界面展示实际采集到的量 |
| 自动入库污染词库 | 中 | 默认确认模式 + 只占空码位 + 可撤回，见 `M8-APPLY-002/003`、`M8-MANAGE-002` |
| 分词质量差导致垃圾候选 | 中 | jieba + N-gram 新词发现 + 多重过滤 + 人工确认 |
| 候选池无限膨胀 | 低 | 时间衰减淘汰，见 `M8-LEARN-006` |
| 采集拖慢用户输入 | 中 | 独立后台任务 + 事件队列解耦，见 `M8-CAPTURE-006` |
| 频繁写短语库触发输入法重载 | 中 | 批量入库 + 周期触发，见 `M8-APPLY-005` |
| 杀毒软件将输入监听判为可疑行为 | 中 | 代码签名（[`NFR-SEC-006`](../20-nonfunctional.md)）+ 提交白名单 + 路径 A 不触发此问题 |

## 14. 建议的分期

| 期 | 内容 | 交付价值 |
|---|---|---|
| **一期** | `CORPUS` + `LEARN` + `APPLY` + `MANAGE` | 用户可导入自己的文章/笔记/聊天记录，一键提取并补入个人新词。**零隐私风险，已能解决大部分场景** |
| **二期** | `CAPTURE` + `PRIV` | 全自动学习。需完整的隐私设计与充分的用户沟通 |

若资源有限，**只做一期也是完整可用的功能**。
