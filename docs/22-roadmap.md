## 3. 实施阶段

### 排序原则

按用户决策：**UI/UX 与应用外壳前置**。产品先长出完整的「骨架」—— 所有导航、页面、主题都在，未实现的功能以占位形态呈现（[`UX-INTERACT-013`](./21-ui-ux.md#61-占位状态规范)），此后逐个模块把占位替换为真实功能。

这么排的收益：

- 第一个可运行版本来得早，产品形状立刻可见、可评审、可改
- UI 框架、主题、导航、任务调度、错误呈现这些**横切基础设施**一次做对，后续模块直接复用
- 每个模块完成就能立刻看到效果，反馈闭环短

**代价与对冲**：最高风险的 TSF 写入路径（`R1`）被推后到 `S3`。为避免「做到一半发现方案不可行」，`S0` 期间**并行**进行 TSF 技术预研（见 [§5](#5-风险处置策略)），用最小原型验证四项底层能力后再进入 `S1`。

---

### 技术预研

**在 S1 开工前**用最小原型验证以下四项，避免方案性返工。这是把「写入闭环」推后到 S3 的必要对冲：

| # | 验证项 | 判定标准 |
|---:|---|---|
| 1 | `windows` crate 调用 `ITfInputProcessorProfileMgr` 激活/停用五笔 Profile | 能成功切换且系统输入法状态随之变化 |
| 2 | `SetNamedSecurityInfo` 完成 TrustedInstaller → Administrators → TrustedInstaller 所有权往返 | 往返后 `icacls` 输出与初始一致 |
| 3 | Task Scheduler COM 控制 `MsCtfMonitor` 任务的启停 | 能 End 与 Run，且 `ctfmon.exe` 行为符合预期 |
| 4 | 数十万行数据在 TanStack Virtual（或等价方案）下的滚动帧率 | ≥ 55 fps |

**任一项不通过，都必须在 S1 开工前重新评估架构方案。**
