## 1. `.lex` 微软五笔码表（二进制）

**魔数**：`imscwubi`（ASCII，8 字节）
**字节序**：小端
**文本编码**：UTF-16LE
**来源**：`lexFile.aardio:216-286`（读）、`lexFile.aardio:337-417`（写）

### 1.1 文件布局

```
0x0000  ┌────────────────────────────┐
        │  文件头 (64 字节)           │
0x0040  ├────────────────────────────┤
        │  字母索引 (26 × 4 = 104)    │
0x00A8  ├────────────────────────────┤
        │                            │
        │  记录区（变长，按编码字典序）  │
        │                            │
fileSize└────────────────────────────┘
```

### 1.2 文件头（0x00 – 0x40）

| 偏移 | 大小 | 类型 | 字段 | 值 / 说明 |
|---:|---:|---|---|---|
| `0x00` | 8 | `BYTE[8]` | `magic` | `"imscwubi"` |
| `0x08` | 2 | `WORD` | `majorVersion` | `1` |
| `0x0A` | 2 | `WORD` | `minorVersion` | `1` |
| `0x0C` | 4 | `INT32` | `indexOffset` | `0x40` — 字母索引起点 |
| `0x10` | 4 | `INT32` | `tableOffset` | `0xA8` — 记录区起点 |
| `0x14` | 4 | `INT32` | `fileSize` | 文件总字节数。**写入时最后回填** |
| `0x18` | 4 | `INT32` | `unknown` | 常量 `0x78563412`。用途未知，原项目原样写入 |
| `0x1C` | 36 | `BYTE[0x24]` | `reserved` | 全 0 |

> **读取端注意**：原项目读取时只解析到 `fileSize`（`0x18` 之前），后续字段跳过。新实现应校验 `magic`，其余字段容错。

### 1.3 字母索引（0x40 – 0xA8）

26 个 `INT32`，对应字母 `a`–`z`。

| 索引 | 含义 |
|---|---|
| `alphaIndex[0]` | 首字母为 `a` 的第一条记录，**相对 `tableOffset`（0xA8）的偏移** |
| `alphaIndex[1]` | 首字母为 `b` 的第一条记录偏移 |
| … | … |
| `alphaIndex[25]` | 首字母为 `z` 的第一条记录偏移 |

**生成算法**（`lexFile.aardio:356-406`）：

```
prevAlpha = 'a' - 1                      // 96
对排序后的每个 code:
    while prevAlpha < code[0]:            // code 首字节
        prevAlpha += 1
        alphaIndex[prevAlpha - 96] = 当前文件位置 - 0xA8
    写入该 code 的全部记录

// 收尾：补齐剩余字母
while prevAlpha < 'z':
    prevAlpha += 1
    alphaIndex[prevAlpha - 96] = 当前文件位置 - 0xA8
```

若某字母无任何编码，其索引值等于下一个有数据字母的起始偏移（即区间长度为 0）。

> **重要前置条件**：写入前必须对全部编码做**字典序升序排序**（`table.sort(inputCodes)`），否则索引失效。

### 1.4 记录布局（0xA8 起）

每条记录为一个「编码 → 单个词条」的映射。同一编码的多个词条 = 多条记录连续排列。

| 偏移 | 大小 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| `+0x00` | 2 | `WORD` | `length` | **整条记录字节数** = `16 + textBytes` |
| `+0x02` | 2 | `WORD` | `weight` | 权重，越小越靠前（1–65535） |
| `+0x04` | 2 | `WORD` | `codeLength` | 编码字符数（1–4） |
| `+0x06` | 8 | `WORD[4]` | `code` | 编码，UTF-16LE，不足 4 字符补 `0x0000` |
| `+0x0E` | 变长 | `BYTE[]` | `text` | 词条，UTF-16LE，**不含终止符** |
| `+0x0E+n` | 2 | `BYTE[2]` | `terminator` | `0x0000` |

**长度关系**：`length = 14（固定头）+ textBytes + 2（终止符）= 16 + textBytes`
其中 `textBytes = 词条 UTF-16 字符数 × 2`。

**读取伪码**：

```
seek(tableOffset)
while pos < fileSize:
    length      = read_u16()
    weight      = read_u16()
    codeLength  = read_u16()
    codeRaw     = read_bytes(8)                    // 4 × UTF-16LE
    code        = utf16le_decode(codeRaw)[..codeLength]
    textBytes   = length - 16
    text        = utf16le_decode(read_bytes(textBytes))
    skip(2)                                        // 终止符
```

### 1.5 权重的隐式递增规则

写入时（`lexFile.aardio:379-390`），同一编码下的词条按数组顺序遍历：

```
weight = 0
for word in words:
    if 该词有显式权重:
        weight = 显式权重
    else:
        weight = weight + 1        // 在上一个权重基础上 +1
    写入记录(weight)
```

即：**无显式权重的词条，其权重紧跟前一个词条递增**。这保证了即使只有部分词条带权重，候选顺序仍稳定。

### 1.6 边界与陷阱

| 项 | 说明 |
|---|---|
| 编码长度 | 硬上限 4 字符。超长编码在写入时会截断（`WORD code[4]` 只有 8 字节） |
| 词条长度 | `length` 是 `WORD`，故 `textBytes ≤ 65535 - 16`，即词条最长约 32,759 个 UTF-16 字符 |
| 重复词条 | 写入时不去重（原项目有一行 `//if(word==words[i-1])continue;` 被注释掉） |
| 空编码/空词条 | 未做防御，需在新实现中显式拒绝 |
| 文件大小 | 完整五笔码表可达数 MB、数十万条记录 |

## 2. EUDP 用户短语库（二进制）

**魔数**：`mschxudp`（ASCII，8 字节）
**字节序**：小端
**文本编码**：UTF-16LE
**来源**：`phrase.aardio:11-104`（读）、`phrase.aardio:186-366`（写）

### 2.1 文件位置与双写

| 路径 | 说明 |
|---|---|
| `%APPDATA%\Microsoft\InputMethod\Chs\ChsWubiEUDPv1.lex` | v1 格式 |
| `%APPDATA%\Microsoft\InputMethod\Chs\ChsWubiEUDPv2.lex` | v2 格式 |

**读取策略**（`phrase.aardio:368-391` `getWubiUdpPrimaryPath`）：

1. 若 v2 不存在 → 用 v1
2. 若 v1 不存在 → 用 v2
3. 都存在 → 取**最后写入时间较新**的那个

**写入策略**（`phrase.aardio:186-366`）：先删除两个文件，写入 v2 完整内容，再**原样复制**为 v1。两个文件内容完全相同。

> 系统仅支持 **Win10 1703（Build 15063）及以上**。低版本无 EUDP 能力，原项目在 UI 层拦截（`dlg/dict/phrase.aardio:21-30`）。

### 2.2 文件布局

```
0x0000  ┌────────────────────────────┐
        │  文件头 (64 字节)           │
0x0040  ├────────────────────────────┤
        │  偏移表 (count × 4 字节)     │
phraseStart ├────────────────────────┤
        │                            │
        │  条目区（按编码字典序）        │
        │                            │
phraseEnd└───────────────────────────┘
```

### 2.3 文件头（0x00 – 0x40）

| 偏移 | 大小 | 类型 | 字段 | 值 / 说明 |
|---:|---:|---|---|---|
| `0x00` | 8 | `BYTE[8]` | `magic` | `"mschxudp"` |
| `0x08` | 4 | `INT32` | `magic2` | 常量 `0x00600002` |
| `0x0C` | 4 | `INT32` | `version` | `1` |
| `0x10` | 4 | `INT32` | `phraseOffsetStart` | `64`（`0x40`）— 偏移表起点 |
| `0x14` | 4 | `INT32` | `phraseStart` | `64 + 4 × count` — 条目区起点 |
| `0x18` | 4 | `INT32` | `phraseEnd` | 文件总字节数。**写入时最后回填** |
| `0x1C` | 4 | `INT32` | `count` | 条目总数 |
| `0x20` | 4 | `INT32` | `timestamp` | Unix 时间戳（写入时刻） |
| `0x24` | 28 | `BYTE[28]` | `reserved` | 全 0 |

### 2.4 偏移表（0x40 起）

`count` 个 `INT32`，第 `i` 项 = 第 `i` 条条目**相对 `phraseStart` 的字节偏移**。

**读取时的哨兵技巧**：在数组尾部追加 `phraseEnd - phraseStart`，使得每条条目的总长度可由「下一项 − 当前项」求得，最后一条也不例外。

### 2.5 条目布局

| 偏移 | 大小 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| `+0x00` | 2 | `WORD` | `cbSize` | 固定 `16`。**读取时必须校验**，不等于 16 视为格式不支持 |
| `+0x02` | 2 | `WORD` | `cbSize2` | 固定 `16` |
| `+0x04` | 2 | `WORD` | `offset` | 文本区相对本条目起点的偏移 = `16 + (codeChars + 1) × 2` |
| `+0x06` | 1 | `BYTE` | `candidate` | 候选位序，**1 起**。决定该短语在候选列表中的位置 |
| `+0x07` | 1 | `BYTE` | `unknown` | 常量 `6` |
| `+0x08` | 1 | `BYTE` | `unknown2` | 常量 `0` |
| `+0x09` | 1 | `BYTE` | `deleted` | 非 0 表示已删除，**读取时跳过该条** |
| `+0x0A` | 2 | `WORD` | `reserved` | 0 |
| `+0x0C` | 4 | `INT32` | `reserved2` | 0 |
| `+0x10` | 变长 | UTF-16LE | `code` | 编码 + `0x0000` 终止符 |
| `+offset` | 变长 | UTF-16LE | `text` | 短语文本 + `0x0000` 终止符 |

**长度推导**：

```
codeCharsWithNul = (offset - cbSize) / 2          // 含终止符
textCharsWithNul = (nextOffset - thisOffset - offset) / 2
textChars        = textCharsWithNul - 1           // 实际字符数
```

> 若 `textCharsWithNul < 0`，原项目直接跳过该条（`phrase.aardio:82-85`）—— 说明存在损坏文件的可能，新实现应保留同等容错。

### 2.6 排序要求

写入前按**编码字典序升序**排序（`phrase.aardio:314`）。同一编码的多条按 `candidate` 排列。

## 3. 文本码表方言

**来源**：`lexFile.aardio:34-213`（`addText`）

这是原项目最有价值也最复杂的部分：**用一个解析器同时兼容 6+ 种社区码表格式**，无需用户指定格式。

### 3.1 预处理（按顺序执行）

| 步骤 | 操作 | 正则 / 规则 |
|---|---|---|
| 1 | 剥离 YAML front matter | `---\s\n ... \n...\s*\n?` 整段删除（Rime 码表常见） |
| 2 | 剥离注释行 | 以 `#` 开头（可紧跟一个 Tab）的整行删除 |
| 3 | 检测 `[Text]` 描述头 | 匹配 `\[Text\]\s*\n\s*`，其前为描述区，其后为正文 |
| 4 | 检测极点五笔标记 | 描述区同时包含 `~:生僻字词` 与 `^:用户词组` → 置 `jidian` 标志 |
| 5 | 检测微软码表格式 | 正文首行匹配 `^[^a-z]+[a-z\s]+\r?\n` → 走专用分支并**提前返回** |

#### 微软码表专用分支

行格式：`词条<非字母>` + `编码<字母/空格>`，即**词前码后、一行多码**。

```
逐行匹配  ^([^a-z]*)([a-z\s]+)$
  → words = 组1, code = 组2
  code 按 \s+ 分割为多个编码，每个编码都映射到该词条
```

此分支**不解析权重**。

### 3.2 主循环行格式（按尝试顺序）

对每一行依次尝试以下模式，命中即处理：

| # | 名称 | 正则 | 提取 | 说明 |
|---|---|---|---|---|
| **A** | 码前词后 + 升序权重 | `^([a-z]{1,4})\s+(\S*)\s+(\d+)\s*$` | code, words, weight | 权重直接使用，越小越靠前 |
| **B** | 短语格式 | `([a-z]+)\s*=\s*(\d+)\s*,\s*(.+)` | code, weight, words | `ysxb=1,短语` |
| **C** | 码前词后 | `^([a-z]{1,4})\s+(\S.*)\s*` | code, words | words 可含空格 → 后续按 `\s+` 拆分为多词（**一码一行**） |
| **D** | 词前码后 + 降序权重 | `^(\S+)\s+([a-z]{1,4})\s+(\d+)\s*[a-z]*\s*$` | words, code, weight | **权重取反**：`w' = 0xFFFF − w` |
| **E** | 词前码后 | `^(\S+)\s+([a-z]{1,4})\s*$` | words, code | |
| **F** | 词前码后 + 一行多码 | `^(\S+)\s+([a-z\s]+)$` | words, codes | codes 按 `\s+` 拆分，每个编码都映射该词 |

**控制流**（`lexFile.aardio:85-177`）：

```
A 命中 或 B 命中 → 记录并 continue
否则 C 命中 → 跳过 D/E/F，落到「多词拆分」处理
否则依次尝试:
    D 命中 → 记录并 continue
    E 命中 → 落到「多词拆分」
    否则 F 命中 → 记录并 continue
多词拆分: words 按 \s+ 分割，每个片段解转义后作为独立词条压入 code
```

> **已知死代码**：`lexFile.aardio:135-137` 的 `if(codeWeight[0]){ continue; }` 中 `codeWeight[0]` 永不为真（`codeWeight` 以编码字符串为键）。新实现应省略。

### 3.3 降序权重归一化

D 模式的权重经 `0xFFFF − w` 反转后，可能落在很大的数值区间。原项目做一次平移（`lexFile.aardio:179-187`）：

```
descWeightMin = min(所有 D 模式产生的 w')
if descWeightMin > 5000:
    所有 D 模式权重 w'' = w' - descWeightMin + 5000
```

即把最小权重拉到 5000，保留相对顺序。**目的**：给后续手工插入的高优先级词条（权重 < 5000）留出空间。

### 3.4 极点五笔标记清理

当 `jidian` 标志置位时（`lexFile.aardio:189-212`）：

1. **清空全部权重数据**（`codeWeight = {}`）
2. 遍历所有词条：

| 首字符 | 处理 |
|---|---|
| `^` | 删除该词条（用户词组标记） |
| `$` | 删除该词条 |
| `!` | 删除该词条 |
| `~` | 去掉首字符，保留其余（生僻字词标记） |

3. 若某编码下词条被清空，则移除该编码。

### 3.5 输出格式矩阵

`tostring(reverse, singleLine, sortWeight, toPhrase)`（`lexFile.aardio:889-1051`）产生 7 种输出：

| reverse | singleLine | sortWeight | toPhrase | 输出格式 | 示例 |
|---|---|---|---|---|---|
| ✗ | ✗ | ✗ | – | 码前词后 | `duyr\t码前词后` |
| ✗ | ✓ | – | – | 码前词后 一码一行 | `gdgt\t词1\t词2\t词3` |
| ✗ | ✗ | ✓ | ✗ | 码前词后 升序权重 | `duyr\t词\t1` |
| ✓ | ✗ | ✗ | – | 词前码后 | `词前码后\tyudr` |
| ✓ | ✓ | – | – | 词前码后 一行多码 | `一行多码\tgt gtqd` |
| ✓ | ✗ | ✓ | – | 词前码后 降序权重 | `词\tyudr\t65534` （`0xFFFF − w`） |
| ✗ | ✗ | ✓ | ✓ | 短语格式 升序号 | `ysxb=1,短语` （按权重排序后重编号） |

所有输出的词条都经过**空白转义**（见 [§8](#8-空白字符转义)），行尾统一 `\r\n`。

### 3.6 文件编码探测

原项目通过 `fsys.codepage.load` 自动识别（`lexFile.aardio:281`），支持：

- UTF-8（含/不含 BOM）
- UTF-16LE / UTF-16BE（含 BOM）
- 系统 ANSI 代码页（简体中文环境下即 GBK）

导出时：`saveTxt` 固定输出 **UTF-16LE**（`lexFile.aardio:419`）；CSV 导出输出 **UTF-8 with BOM**（`dlg/dict/lex.aardio:317`）。

### 3.7 支持的容器格式

| 扩展名 | 处理方式 | 来源 |
|---|---|---|
| `.lex` | 二进制，校验 `imscwubi` 魔数 | `lexContents.aardio:328-347` |
| `.lex.lzma` | LZMA 解压后按 `.lex` 处理 | `lexContents.aardio:309-327` |
| `.txt` / `.yaml` / `.ini` | 文本方言解析 | `lexContents.aardio:227-242` |
| `.csv` | 每行 = `[编码, 词1, 词2, ...]`；首行首列须匹配 `^[a-z]+$` 否则拒绝 | `lexContents.aardio:275-308` |
| `.json` | 数组的数组，结构同 CSV；同样做首行校验 | `lexContents.aardio:243-274` |

## 4. 短语文本方言

**来源**：`phrase.aardio:186-366`（文本 → EUDP）、`phrase.aardio:125-176`（EUDP → 文本）

### 4.1 预处理

删除所有 `/* ... */` 注释（非贪婪，跨行）。

### 4.2 行格式（按尝试顺序）

| # | 名称 | 正则 | 提取 | 示例 |
|---|---|---|---|---|
| **P1** | 等号+逗号序号 | `([a-z]+)\s*=\s*(\d+)\s*,\s*(.+)` | code, order, text | `zzsj=2,%yyyy%年%MM%月` |
| **P2** | 逗号序号+等号 | `([a-z]+),(\d+)=#?(.*)` | code, order, text | `zzxx,1=测试短语` |
| **P3** | 纯等号 | `([a-z]+)\s*=\s*(.*)` | code, text | `aar=aardio` |
| **P4** | 空白分隔+尾序号 | `([a-z]+)\s+(.+?)\s+(\d+)$` | code, text, order | `zzxx\t测试短语\t1` |
| **P5** | 空白分隔 | `([a-z]+)\s+(.+)` | code, text | `zzxx\t测试短语` |
| **P6** | 词前码后 | `^([^\s]\S*)\s+([a-z]{1,4})[\s\d]*$` | text, code | `测试短语\tzzxx` |

**P4 的触发条件**：行尾匹配 `\s+\d+$`（先做预检再套用 P4 正则）。

### 4.3 多行文本

当 P2 或 P3 匹配后 **text 为空**（等号后立即换行），进入 `multiline` 状态：后续行**追加**到上一条短语的文本，用 `\n` 连接，直到遇到下一个可识别的行格式。

```
zzdz=
第一行
第二行
```
→ 编码 `zzdz` 的短语文本为 `第一行\n第二行`

### 4.4 符号数组语法 `$[...]`

当解析出的 text 匹配 `^\$\[(.+)\]$` 且**未显式指定序号**时，展开为多个候选：

| 数组内容 | 分割规则 |
|---|---|
| 含空格 | 先把连续多空格归一为单空格，再按空格分割 |
| 不含空格 | **按字符分割**（每个字符一个候选） |

```
zzkh=$[「」『』〖〗《》]          → 8 个候选，逐字符
zzbg=$[乾☰ 兑☱ 离☲ 震☳]        → 4 个候选，按空格
```

展开后 `candidate` 依次为 1, 2, 3, …，并更新该编码的序号计数器。

> **这是 WubiLex 对微软短语的功能扩展**，Windows 系统短语设置界面不支持此语法（`phraseHelp.aardio:7`）。

### 4.5 序号自动分配

未显式指定序号时：`order = 该编码已用最大序号 + 1`。序号计数器 `orderMap` 按编码维护。

### 4.6 时间变量

P2 分支支持两套写法，`$xxx` 形式会先被映射为 `%xxx%` 形式：

| `$` 别名 | 映射为 | 含义 |
|---|---|---|
| `$year` | `%yyyy%` | 4 位年 |
| `$year_yy` | `%yy%` | 2 位年 |
| `$month_mm` | `%MM%` | 2 位月 |
| `$month` | `%M%` | 月（不补零） |
| `$day` / `$day_dd` | `%dd%` | 2 位日 |
| `$fullhour` | `%HH%` | 24 小时制 |
| `$minute` | `%mm%` | 分 |
| `$second` | `%ss%` | 秒 |

`%...%` 变量由**微软五笔输入法在上屏时求值**，WubiLex 只负责原样写入。

> **已知陷阱**：在 Windows「设置 → 五笔 → 用户自定义短语」界面编辑过短语后，时间变量会被固化为当时的具体时间，失去动态性（`phraseHelp.aardio:15`）。

### 4.7 EUDP → 文本的反向输出

`load()` 对每个编码：

1. 按 `candidate` 升序排序
2. **尝试压缩为 `$[...]` 数组**：当且仅当该编码下**每一条**都满足
   - `candidate == 数组下标`（序号连续无缺口）
   - 文本长度 ≤ 2 个 UTF-16 code unit（允许 emoji 的代理对）

   则输出 `code\t$[c1 c2 c3 ...]\r\n`
3. 否则逐条输出 `code\ttext\tcandidate\r\n`

所有文本经过空白转义。

### 4.8 默认短语库

原项目内置 36 条默认短语（`phrase.aardio:393-428`），涵盖：括号、标点、表情、数学符号、箭头、圆圈数字、罗马数字、带圈字母、天气、希腊字母、日文假名、拼音声调、西里尔字母、法文字母、地支、八卦、国际象棋、扑克、音乐符号。

新项目应保留同等规模的默认短语库作为开箱体验。

## 5. 词频文件

**来源**：`lexFile.aardio:569-614`（`loadWordWeight`）、`lexFile.aardio:546-568`（`saveWordWeight`）

**格式**：UTF-8 纯文本，每行一条。

```
<词条><制表符或空白><权重>
```

| 项 | 约束 |
|---|---|
| 编码 | UTF-8（无 BOM） |
| 权重范围 | 1 – 65535 |
| 排序语义 | **越小越靠前** |
| 解析正则 | `(:+)\s+(\d+)` — 词条为任意非空白字符序列 |
| 默认权重 | 词条不在词频文件中时取 `0xF36B`（62315） |

**上游文件**：`http://wubi.aardio.com/download/word-weight.lzma`
**本地缓存**：`%APPDATA%\aardio\std\wubi\word-weight2.txt`

### 5.1 权重重算算法

`loadWordWeight(path, reorder, fixedSingleChar)`：

| `reorder` | `fixedSingleChar` | 行为 |
|---|---|---|
| `false` | – | **保持原有候选顺序**，仅重写权重值使其单调递增 |
| `true` | `false` | 完全按词频文件重排每个编码下的候选顺序 |
| `true` | `true` | 首候选为单字的编码保持顺序不变，其余重排 |

「保持顺序」模式的权重生成：

```
weight[words[0]] = 词频[words[0]] 或 0xF36B
for i in 1..n:
    w = 词频[words[i]]
    if w 不存在 或 w <= weight[words[i-1]]:
        w = weight[words[i-1]] + 1        // 强制递增，保序
    weight[words[i]] = w
```

**来源**：`spellingTable.aardio:19-36`

**格式**：UTF-8 纯文本，每行一条。


| 字体文件 | 适用版本 | 下载地址 |
|---|---|---|
| `wubi-lex-etymon-v5.otf` | 86 / 98 / 06 / 091 / 郑码 / 小鹤音形 / 表形码 | `download/spelling/fonts/wubi-lex-etymon-v5.lzma` |
| `wubi-lex-etymon-092.otf` | 092 | `download/spelling/fonts/wubi-lex-etymon-092.lzma` |

### 6.2 分发

| 项 | 值 |
|---|---|
| 上游 | `http://wubi.aardio.com/download/spelling/data-table/{version}.lzma` |
| 本地缓存 | `%APPDATA%\aardio\std\wubi\spelling-data-table\v2\{version}.txt` |
| 版本代号 | `86` / `98` / `06` / `091` / `092` / `xhyx` / `zhengma` |
| 仓库内源文件 | `wubi-lex/sepllingData/*.txt`（未压缩原始数据） |
| 构建工具 | `wubi-lex/sepllingData/build.aardio`（编辑器 + LZMA 打包） |

> 仓库目录名 `sepllingData` 为原项目拼写错误（应为 `spellingData`），新项目应更正。

### 6.3 词组拆字的组合规则

数据表中只有单字（及少量词组）条目。词组拆字时按字长采用不同的取根策略（`dlg/spelling.aardio:198-229`）：

| 词长 | 取根规则 | 前置条件 |
|---|---|---|
| 2 | 字1 的前 2 根 + 字2 的前 2 根 | 两字各自 ≥ 2 根 |
| 3 | 字1 首根 + 字2 首根 + 字3 的前 2 根 | 字3 ≥ 2 根 |
| 4 | 字1、2、3、4 各取首根 | 各字 ≥ 1 根 |
| >4 | 字1、2、3 各取首根 + **末字**首根 | 各字 ≥ 1 根 |

任一字在数据表中缺失 → 整个词组不显示拆字。

### 7.1 直接判定（命中即返回）

按顺序测试，任一组全部命中即返回：

## 8. 空白字符转义

**来源**：`lib/wubi/text.aardio`

码表与短语的**文本字段可能包含空白字符**，但存储格式以空白作分隔符，故需转义。

### 8.1 编码（写出时）

对文本中的**所有空白字符**（`\s`）转为 `%` + 两位大写十六进制：

| 字符 | 转义 |
|---|---|
| 空格 `U+0020` | `%20` |
| 制表符 `U+0009` | `%09` |
| 回车 `U+000D` | `%0D` |
| 换行 `U+000A` | `%0A` |

> 编码端用 `string.replace(txt, "\s", hexEncode)` —— 会转义**任何**匹配 `\s` 的字符，理论上包括垂直制表符 `%0B`、换页符 `%0C`。

### 8.2 解码（读入时）

**仅识别上表 4 种**（`text.aardio:12-14` 的模式串 `<\%20>|<\%09>|<\%0D>|<\%0A>`）。

> **不对称缺陷**：编码端可能产出 `%0B` / `%0C`，解码端不认识，会原样保留为字面文本。新实现应统一两端的字符集。

### 8.3 应用范围

| 场景 | 是否转义 |
|---|---|
| 文本码表导出（`saveTxt` / `tostring`） | ✓ 编码 |
| 文本码表导入（`addText`） | ✓ 解码 |
| EUDP 短语写入（`saveToSystem`） | ✓ 解码后写入二进制 |
| EUDP 短语读出（`load`） | ✓ 编码后输出文本 |
| `.lex` 二进制读写 | ✗ 二进制字段无需转义 |
| CSV / JSON 导出 | ✗ 由容器格式自行处理转义 |

## 9. Rust 实现建议

| 格式 | 建议方案 |
|---|---|
| `.lex` / EUDP 二进制 | 手写 `nom` 解析器或直接 `byteorder`；**不要**用 `#[repr(C)]` 直接 transmute（`length` 变长、对齐不保证） |
| UTF-16LE | `widestring` crate 或 `String::from_utf16_lossy` |
| 文本编码探测 | `chardetng` 探测 + `encoding_rs` 解码；BOM 优先 |
| 文本方言解析 | `regex` crate，预编译为 `once_cell::Lazy<Regex>`；行级并行用 `rayon` |
| CSV | `csv` crate |
| JSON | `serde_json` |
| LZMA | `lzma-rs`（注意上游是 **LZMA alone** 格式，非 xz） |
| TAR | `tar` crate |

### 建议的验收测试集

1. **往返测试**：`.lex` → 内存模型 → `.lex`，字节级一致
2. **交叉测试**：`.lex` → 文本（7 种格式）→ `.lex`，语义一致
3. **方言覆盖**：为 §3.2 的 6 种行格式 + 微软码表分支各准备样本
4. **版本探测**：为 8 种方案各准备一份最小码表，断言 `getVersion` 结果（含修复后的 `xfxy` 用例）
5. **EUDP 往返**：短语文本 → EUDP → 短语文本，含 `$[...]` 数组、多行文本、时间变量
6. **边界**：空文件、只有文件头、`count = 0`、损坏的偏移表、`deleted != 0` 的条目
